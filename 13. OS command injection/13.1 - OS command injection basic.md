



# 1. Definition

`OS command injection` is also known as `shell injection`. It allows an attacker to `execute` operating system (OS) commands on the server that is running an application, and typically fully compromise the application and its data. 

Often, an attacker can leverage an OS command injection vulnerability to compromise other parts of the hosting infrastructure, and exploit trust relationships to pivot the attack to other systems within the organization.

---

# 2. Detection

The process for detecting and exploiting basic OS Command Injection vulnerabilities is straightforward: append commands through injection methods and observe if output changes from expected results. This indicates successful exploitation.

For advanced cases, fuzzing methods or code reviews may be needed to identify potential vulnerabilities, gradually building payloads until achieving command injection.

---

For example, A shopping application retrieves stock info via URL parameters passed to a shell command:

`stockreport.pl 381 29`

With no defenses against OS command injection, an attacker can submit `& echo aiwefwlguh &` as the `productID`, transforming the executed command into:

`stockreport.pl & echo aiwefwlguh & 29`

The `&` separator splits this into three sequential commands, producing:

`Error - productID was not provided aiwefwlguh 29: command not found`

This reveals all three commands ran: `stockreport.pl` failed without its arguments, `echo` printed the injected string, and `29` was interpreted as a command. Wrapping the payload in `&` separators isolates it from surrounding input, preventing context from interfering with execution.

## 2.1 - Command Injection Methods

To inject an additional command to the intended one, we may use any of the following operators:

| Injection Operator | Injection Character | URL-Encoded Character | Executed Command                                    |
|--------------------|---------------------|------------------------|-----------------------------------------------------|
| Semicolon          | `;`                 | `%3b`                  | Both                                                |
| New Line           | `\n`                | `%0a`                  | Both                                                |
| Background         | `&`                 | `%26`                  | Both (second output generally shown first)          |
| Pipe               | `\|`                 | `%7c`                  | Both (only second output is shown)                  |
| AND                | `&&`                | `%26%26`               | Both (only if first succeeds)                       |
| OR                 | `\|\|`                | `%7c%7c`               | Second (only if first fails)                        |
| Sub-Shell          | `` ` ` `` (no space)         | `%60%60`               | Both (Linux-only)                                   |
| Sub-Shell          | `$( )`              | `%24%28%29`            | Both (Linux-only)                                   |

---

## 2.2 - Command Injection Operators

We can inject commands using operators so both/either commands execute. Simply write expected input, add an operator, then add your command.

**Note:** Unix-only operators like backticks (``) or sub-shell (`$()`) work only on Linux/macOS.

Most operators work across all platforms regardless of:
- Web application language (PHP, .Net, NodeJS)
- Framework
- Back-end server (Linux, Windows, macOS)

**Exception:** Semi-colon (`;`) works with Windows PowerShell but not with Windows Command Line (CMD).

## 2.5 - OS Command Injection Techniques

**Command Separators (Cross-Platform)**
* `&` - Run commands sequentially
* `&&` - Run second command if first succeeds
* `|` - Pipe output to next command
* `||` - Run second command if first fails

**Unix-Only Separators**
* `;` - Run commands sequentially
* Newline (`0x0a` or `\n`)

**Unix Command Execution**
* `` `command` `` - Execute command and substitute output
* `$(command)` - Execute command and substitute output

**Breaking Out of Quotes**
When input is within quotes, terminate them first (`"` or `'`) before using metacharacters.

**Note: Different metacharacters behave differently and may affect your ability to retrieve command output (in-band vs. blind exploitation).**
