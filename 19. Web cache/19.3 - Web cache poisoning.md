# 1. WCP basic

## 1.1 - The basic idea

Imagine a cache as a photocopier sitting in front of a real employee (the server). To save time, the copier keeps copies of common answers on hand and hands those out instead of bothering the employee every time someone asks the same question.

**Web cache poisoning** is when an attacker tricks the employee into writing something malicious on a piece of paper — and then tricks the copier into saving *that* bad copy and handing it out to everyone who asks afterward.

It happens in two steps.

---

## Step 1 — Trick the server into producing a bad response

The attacker looks for some part of the request that the **server** reacts to, but that the **cache** ignores when deciding "have I seen this exact request before?" This ignored piece is called an **unkeyed input** — usually a header.

```http
GET /home HTTP/1.1
Host: example.com
X-Forwarded-Host: evil.com
```

If the server carelessly uses `X-Forwarded-Host` to build something on the page — like a link or a script tag — the response might now quietly contain:

```html
<script src="https://evil.com/script.js"></script>
```

The cache never looked at that header, so as far as it's concerned, nothing suspicious happened.

---

## Step 2 — Get that bad response cached

Since the cache only checks the parts of the request it actually cares about (usually the URL path and `Host` header), it sees a perfectly normal request for `/home` and stores the poisoned response as if it were the real one.

From that point on, **every future visitor** to `/home` — with no special header, no interaction with the attacker at all — gets served the malicious version straight from the cache.

---

## Why this is so dangerous

The attacker doesn't need to attack every visitor one by one. They poison the cache **once**, and the cache does the work of spreading the attack for them.

Depending on what gets injected, this can lead to:

- **XSS** — malicious JavaScript runs in every visitor's browser
- **Open redirect** — visitors get silently sent to a phishing site
- **JavaScript injection** — attacker-controlled scripts load on a page users trust

If the poisoned page is something high-traffic, like a homepage, this single crafted request could end up affecting thousands of users before anyone notices.
